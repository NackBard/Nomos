# D-058. Этап 14: Java

Ответы пользователя в начале этапа (2026-11-06), закрывают открытый вопрос 13 для Java: JDK берётся из настроек расширения Java (`java.jdt.ls.java.home`, затем `java.home`), затем из `JAVA_HOME`, затем `java` из `PATH`; у каждого кандидата проверяется модуль `jdk.compiler`, встроенный JRE расширения Red Hat Java в поиск не входит (есть ли в нём компилятор, не проверялось). Минимальная версия — JDK 17. Модуль — пакет; зависимости Maven и Gradle не разрешаются, как D-003 для C#. Без подходящего JDK — сообщение с причиной и кнопкой страницы загрузки, остальные анализаторы работают. Проектные решения D-049 (`disabled-by-config`, `message.id` с шаблонами spec и английским `message.text`, UML без новых видов рёбер) подтверждены для Java. Для Kotlin (этап 15) вопрос 13 остаётся открытым: среда JVM общая, но компилятору Kotlin нужен свой пакет.

- **Анализатор `analyzers/java`** на Java 17, только стандартная библиотека и модуль `jdk.compiler`: javac Tree API (`com.sun.source`) и `javax.lang.model`, без внутренних пакетов `com.sun.tools.javac`, поэтому `--add-exports` не нужен. Новых зависимостей нет. JSON читает и пишет свой `Json.java`: в стандартной библиотеке Java разборщика нет. Лексер свой (`Lexer.java`): сканер javac лежит во внутреннем пакете. Тексты правил и практики — `src/nomos/java/rules.json` и `practices.json` из `npm run spec-json`, в jar они ресурсы.
- **Одна компиляция без classpath.** Все `.java` под корнем идут в один `JavacTask`: `parse()`, затем `analyze()` с `-proc:none` и `-XDshould-stop.ifError=FLOW` — без этой опции javac перестаёт атрибутировать классы после первой ошибки, а без classpath ошибки есть почти всегда. Синтаксические ошибки (во время `parse()`) дают `parsed: false` и код 4, ошибки разрешения — одну запись `diagnostics` с кодом `unresolved`. Исходник передаётся javac тем текстом, который прочитал анализатор (BOM снят, переводы строк — `\n`), поэтому смещения дерева и лексера совпадают. Сопоставление дерева с файлом — по URI: javac оборачивает переданные `JavaFileObject`.
- **Модуль — пакет**, id — имя пакета, модуль из многих файлов; без `package` — `(global)`, как в C#. Единица — тип, в том числе вложенный (`пакет.Внешний.Внутренний`); id обобщённого типа без параметров. Функции, которые добавляет javac (конструктор по умолчанию, канонический конструктор записи, `super()` в конструкторе), отбрасываются по `Elements.getOrigin` и по тексту исходника. Перегрузки — с типами параметров в id, как в C#. Подробности — раздел «Java» в `spec/metrics.md`, `spec/paradigms.md`, `spec/structure.md`.
- **Все рёбра `runtime`.** Стирания типа, как в TypeScript, у Java нет. Явный `super(…)` — `call` к базе. Компонент записи — свойство, его чтение через аксессор — `type-ref`, как чтение свойства C#. ATFD считает поля и свойства всех проектных типов, `foreignMembers` — только классов, как в эталоне C# (структура `Money` входит в ATFD `Printer`).
- **Правила** — те же 30, что у Python и TypeScript; PAT, PRN кроме PRN007, FUN001–FUN004, OOP006, CC006–CC008 и SEC002 — `not-supported`, STR001 — «Java has no goto». В spec добавлен шаблон `ALG002.searchHashMap` («A HashSet or HashMap…»): существующие пояснения называли `Dictionary` из C#. Golden SARIF C# изменился только этим ключом в `messageStrings`.
- **Поставка.** `node analyzers/java/run.mjs --jar <файл>` собирает один jar (классы `--release 17`) на все платформы; `scripts/package.mjs` кладёт его в `bundle/java/`. Запись реестра: `["${runtime}", "-jar", "${bundle}/java/nomos-java.jar"]` и `runtime` с `settings`, `environment: ["JAVA_HOME"]`, `home: "bin/java"`, `path: ["java"]`, проверкой `--add-modules jdk.compiler -jar ${bundle}/java/nomos-java.jar manifest` (JRE без компилятора и JDK старше 17 её не проходят) и `installUrl` adoptium.net.
- **Механизм сред расширения обобщён данными реестра** — отступление от «`extension/` не изменился, кроме реестра», как в D-057. У расширения Java нет команды, которая вернула бы путь к JDK, поэтому `RuntimeRequirement` получил необязательные `extension` и `command`, поля `settings` (настройки VS Code для папки) и `environment` (переменные окружения), значение которых — папка установки, `home` — программа внутри неё без суффикса платформы (`programIn` добавляет `.exe` на Windows: Node не запускает `…\bin\java` без него), и `${bundle}` в `check`. Порядок поиска: команда расширения, настройки, переменные, `PATH`. Языковой логики в `extension/` нет, `check-boundary` проходит. Для среды без расширения — своё сообщение с русским переводом, оно перечисляет настройки, переменные и программы `PATH`.
- **Запуск в репозитории.** `analyzers/java/run.mjs` находит JDK 17+ с компилятором (`NOMOS_JAVA`, `JAVA_HOME`, `java` из `PATH`), собирает классы в `analyzers/java/build/` (в `.gitignore`), когда исходники новее, и запускает анализатор; `--test` — тесты (`test/nomos/java/Tests.java`, свой маленький каркас: тестового в стандартной библиотеке нет). CI ставит Temurin 17 — самую старую поддерживаемую версию.
- **Conformance.** Java есть во всех 19 случаях, кроме `patterns` (исключение: правила PAT не написаны); эталоны посчитаны вручную, `parity` дописан везде, где он есть у Python, и совпадает. Отличия формы, которые требует язык: по одному открытому типу на файл, поэтому типы разложены по файлам иначе, чем в C#; скобки по стилю Java на строке объявления, отсюда другие `lines`; в `maintainability` порог `minIndex` 80 (MI функции `add` ≈ 79,0 при трёх строках); в `paradigm-activation` пара «неизменяемый тип с наследованием» — классы с `final`-полями: запись в Java наследовать не может; `Child` даёт ещё и ребро `call` от явного `super(id)`; в `design-smells` структура `Money` — запись; в `complexity-estimates` `new Box().size` даёт и `call`, и `type-ref` (чтение поля), в C# только `call`; в `security-heuristics` интерполяция — `formatted` и `String.format`, SEC002 не реализован; в `partial-failure` сломанный файл без `package` — модуль `(global)`.

Проверено: тесты анализатора (12: шаблоны текстов против spec, manifest, детерминизм, коды возврата, пустая папка, неразрешённый тип по `import`, сгенерированные конструктор и `super()`, id перегрузок и вложенных типов, аксессор записи, практики, текстовый блок одним токеном, запись чисел), `npm run java` — 26 из 26, `npm run all` — 121 из 121 на шести языках с `parity`, `npm run validate`, `dotnet test` (golden обновлён), тесты расширения (43, в том числе поиск среды через настройки и переменные и суффикс `.exe`), `check-boundary`, `check-l10n`, `npm run package -- --bundle-only` (jar 164 КБ; на JDK 17 проверка проходит, на Java 8 нет), отчёт `ci` по репозиторию — шесть языков, 32 с; Java — 230 находок на собственном коде анализатора, ни одного неразрешённого типа. Встроенный jar на папке только с `.java` дал ожидаемые находки (OOP001, SEC001, ALG001 O(n³), ALG002). Не проверено: e2e в настоящем VS Code — он обновлялся и не запустился («Code is currently being updated»); ответ настроек расширения Java (`java.jdt.ls.java.home`) — ставить расширение в тестовый профиль значило бы скачать чужой код; анализатор на Linux (только в CI); установленный `.vsix` руками; большой проект на Java.
