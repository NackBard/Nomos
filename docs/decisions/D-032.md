# D-032. Расширение VS Code (этап 3)

`extension/`: `src/core` (контракты, запуск анализатора, SARIF, подготовка данных для дерева, CodeLens и графа) не импортирует `vscode` и проверяется `npm test`; `src/ui` и `src/extension.ts` — только отображение; `media/graph.js` — страница графа. Команды: `nomos.analyze`, `nomos.showGraph`.

**Зависимости** (`extension/package.json`, версии закреплены): `ajv` 8.17.1 — проверка документов по схемам в рантайме, та же версия, что в harness; `typescript` 5.9.2, `@types/node` 24.3.0, `@types/vscode` 1.90.0 — только сборка. Сборщика нет: `tsc` и `node_modules` в пакете проще, а граф без библиотек — небольшой силовой раскладчик в `media/graph.js`. Схемы копируются из `contracts/` при сборке, чтобы лежать в пакете; источник один.

**Запуск.** Для каждой записи `nomos.json` расширение зовёт `manifest`, затем `analyze --root <абс.> --config <nomos.json> --sarif .nomos/<язык>.sarif`. Путь SARIF относительный, потому что он попадает в `facts.checks.sarifFile`, а в facts не должно быть абсолютных путей. `.nomos/` в `.gitignore`. `manifest`, facts и файл рабочей области проверяются по схемам; незнакомая мажорная версия — отдельное сообщение (на открытый вопрос 9 это даёт ответ «достаточно `schemaVersion`», таблицы совместимости нет). Коды 0 и 4 дают результат, остальные — сообщение со смыслом кода и первой строкой stderr.

**Граница с языком** проверяется `npm run check-boundary` (поиск названий языков, парсеров и расширений исходников) и тестом, где протокол говорит поддельный анализатор несуществующего языка `toy`. Имена метрик в CodeLens — из `spec/metrics.md`, общие для всех языков.

**Что проверено.** `npm run e2e` запускает установленный VS Code на этом репозитории: анализ, Diagnostics, CodeLens, открытие панели графа и представлений. Содержимое деревьев и отрисовка графа этим тестом не проверяются, `media/graph.js` прогонялся один раз на заглушке DOM с реальными данными, глазами не смотрели. `e2e` в CI не включён: нужен VS Code и дисплей.

**Границы.** Рабочие области с несколькими корнями анализируются по очереди. Номера строк CodeLens и Diagnostics относятся к последнему анализу и после правок устаревают до следующего запуска; `nomos.analyzeOnSave` выключен по умолчанию, потому что полный анализ занимает секунды. `--files` не используется (открытый вопрос 3).
