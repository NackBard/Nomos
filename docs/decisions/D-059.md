# D-059. Этап 15: Kotlin

Ответы пользователя в начале этапа (2026-11-06), закрывают открытые вопросы 13 и 14 для Kotlin: компилятор Kotlin едет внутри `.vsix` (на этапе 18 — один языковой пакет Kotlin на все платформы, jar от платформы не зависит); разбор — синтаксическое дерево PSI из компилятора и своё разрешение имён по объявлениям проекта, без резолвера компилятора (K1 устарел, Analysis API в автономном режиме не опубликован стабильно); среда — Java 17+ тем же порядком, что у Java (D-058): настройки расширения Java, `JAVA_HOME`, `java` из `PATH`, но достаточно JRE — модуль `jdk.compiler` не нужен. Анализатор пишется на самом Kotlin. Проектные решения D-049 (`disabled-by-config`, `message.id` с шаблонами spec и английским `message.text`, UML без новых видов рёбер) подтверждены для Kotlin; модуль — пакет, без `package` — `(global)`; зависимости Gradle не разрешаются; разбираются только `.kt`, скрипты `.kts` — нет.

- **Новая зависимость — компилятор Kotlin 2.4.21** (8 октября 2026, последний стабильный выпуск на начало этапа): `kotlin-compiler-embeddable` и то, что ему нужно, с Maven Central. Зачем: родной разборщик Kotlin есть только в компиляторе, другого полного разборщика языка нет, а свой разборщик грамматики Kotlin (строковые шаблоны, мягкие ключевые слова, лямбды с завершающими аргументами) был бы большим и неточным. Версии и суммы SHA-1 (из Maven Central) и SHA-256 (посчитаны при первой загрузке) закреплены в `analyzers/kotlin/deps.json`; `node analyzers/kotlin/run.mjs --fetch` скачивает jar в `analyzers/kotlin/lib/` (в `.gitignore`) и проверяет обе суммы. Во время работы анализатору нужны три jar: `kotlin-compiler-embeddable` (56 МБ), `kotlin-stdlib` и `kotlinx-coroutines-core-jvm` (без него окружение компилятора не поднимается); остальные из `deps.json` (`kotlin-script-runtime`, `kotlin-reflect`, `kotlin-daemon-embeddable`, `kotlin-build-tools-api`, `annotations`) нужны только для сборки. Обновление версии — правка `deps.json` и новое решение.
- **Сборка без kotlinc и Gradle.** `kotlin-compiler-embeddable` содержит CLI-компилятор `K2JVMCompiler`: `run.mjs` собирает им исходники анализатора в `build/classes` (`-jvm-target 17 -Werror`), когда они новее, тем же Java, на котором потом запускает. Тесты — `test/nomos/kotlin/Tests.kt`, свой маленький каркас, как у Java. API окружения компилятора помечен opt-in (`CompilerConfiguration.Internals`, `CoreEnvironmentDeprecation`, `ExperimentalCompilerApi`) и меняется между версиями: это цена PSI из компилятора, обновление версии проверяется сборкой и тестами.
- **Анализатор `analyzers/kotlin`** на Kotlin: PSI (`KotlinCoreEnvironment` и `KtPsiFactory`) для дерева, листья PSI для токенов и комментариев (свой лексер не нужен), свои `Json` и `Resolver`. Разрешение имён (`Resolver`): имена типов — по вложенности, явному `import` (в том числе `as`), своему пакету, `import …*` пакетов проекта, полностью квалифицированному имени и умолчаниям Kotlin/JVM; значения — по локальным областям, неявным получателям (свой класс и его проектные базы, получатель расширения, лямбды `apply`/`run`/`with`) и типам из объявлений и явного создания. `manifest.capabilities.semantic` и `facts.analyzer.semantic` — `false`, как у Python: правила по типам молчат, если тип неизвестен. Подробности — раздел «Kotlin» в `spec/metrics.md`, абзац «Для Kotlin» в `spec/paradigms.md` и раздел «Kotlin» в `spec/structure.md`.
- **Единицы.** Типы (класс, интерфейс, `enum class`, `annotation class`, `object`) и функции верхнего уровня, в том числе расширения — как свободные функции Go и TypeScript. `companion object` — не единица, его члены статические в своём типе; члены объявления `object` тоже статические: `object` в Kotlin — замена статического класса, иначе утилитные объекты получали LCOM4, TCC и находки DSN004/DSN005, которых у статических методов Java нет. Первичный конструктор, если он написан, — функция `constructor` (тело — блоки `init`), поэтому у `data class` `memberCount` на один больше, чем у записи Java с неявным каноническим конструктором. Аксессор с телом — функция `accessor`, в `methodCount`, `memberCount` и WMC не входит.
- **Рёбра** все `runtime`. Вызов конструктора базы в списке супертипов (`: Base(id)`) даёт только `inheritance`, как в C#: он часть объявления, у каждого наследника он есть. Вызов на значении библиотечного типа, известного из объявления, — `call` к этому типу, как в Java; свойство с инициализатором-созданием (`var source = Data()`) даёт и `call`, и `type-ref` от чтения.
- **Признаки парадигм.** Своих видов у Kotlin нет: новый вид потребовал бы перевода в `extension/src/ui/trees.ts`, а расширение на языковом этапе не меняется. `data class` из `val` — `fp.immutable-types`, `sealed` — `oop.abstractions`, функциональные типы и `fun interface` — `fp.higher-order`, функции-расширения — `str.free-functions`.
- **Правила** — те же 30, что у Java; PAT, PRN кроме PRN007, FUN001–FUN004, OOP006, CC006–CC008 и SEC002 — `not-supported`, STR001 — «Kotlin has no goto». Тернарного оператора в Kotlin нет, PRN007 считает только логические операторы условий. OOP001 сообщает только о полях `@JvmField`: обычное свойство `var` — свойство с аксессорами, как у C#. Новых шаблонов в spec нет: тексты находок — существующие шаблоны, `npm run spec-json` пишет `src/nomos/kotlin/rules.json` и `practices.json` (ресурсы jar).
- **Поставка.** `node analyzers/kotlin/run.mjs --bundle <папка>` кладёт `nomos-kotlin.jar` (321 КБ, `Class-Path` называет соседние jar) и три jar компилятора (около 62 МБ) в `bundle/kotlin/`; для сборки jar нужен JDK (`jar`), для работы — любой Java 17+. Запись реестра: `["${runtime}", "-jar", "${bundle}/kotlin/nomos-kotlin.jar"]`, `runtime` как у Java, но с именем «Java 17 or newer» и проверкой `-jar … manifest` без `--add-modules jdk.compiler`; Java 8 её не проходит. `extension/` изменился только в `scripts/package.mjs` (реестр) и в `scripts/check-boundary.mjs` (имя `kotlin` и расширения `.kt`, `.kts` теперь тоже запрещены в коде расширения).
- **Запуск в репозитории.** `nomos.json` и `npm run kotlin`/`all` запускают `node analyzers/kotlin/run.mjs`; CI скачивает jar шагом `--fetch` (около 66 МБ с Maven Central на каждый запуск; кэш не добавлен, чтобы не вводить ещё одно действие) и запускает тесты.
- **Conformance.** Kotlin есть во всех 19 случаях, кроме `patterns` (исключение: правила PAT не написаны); эталоны посчитаны вручную, `parity` дописан везде, где он есть у Java, кроме Halstead и MI в `maintainability`: тип после имени через `:` даёт больше токенов (V = 42 против 30,9 у C#), как у TypeScript и Python, которых там тоже нет. Отличия формы: статические методы — в `companion object`; поле без инициализатора — `lateinit var`; в `complexity-estimates` деление пополам — `while`, как у Python (`for` в Kotlin не делит счётчик); в `oop-cohesion` `var source = Data()` даёт ещё ребро `call`; в `paradigm-activation` у `Child` нет ребра `call` от `super(id)` (как у C#), а записи `Base` и `Child` — классы с первичным конструктором; в `design-smells` `Money` — `data class` с конструктором (`memberCount` 4), `Printer()` — вторичный `constructor`; в `security-heuristics` SQL с подстановкой — строковый шаблон; в `type-structure` перечисление называется `Scale` (а не `Unit`, чтобы не путать с `kotlin.Unit`), `Point` — `data class`.

Проверено: тесты анализатора (13: шаблоны текстов против spec, manifest, детерминизм, коды возврата, пустая папка, тип библиотеки по `import`, id перегрузок и вложенных типов, статические члены `companion object` и `object`, функция-расширение, тип элемента у `it` и переменной цикла, практики, строковый шаблон одним токеном, запись чисел), `npm run kotlin` — 26 из 26, `npm run all` — 140 из 140 на семи языках с `parity`, `npm run validate`, тесты harness, `dotnet test` (golden не изменился), `go test`, тесты TypeScript, Python, Java, `ci` и расширения (43), `check-boundary`, `check-l10n`, `npm run package -- --bundle-only` (встроенный jar работает через `java -jar`, без jar coroutines — нет, на Java 8 проверка не проходит). Отчёт `ci` по репозиторию — семь языков, 54 с; Kotlin — 330 находок на собственном коде анализатора, разбор его 14 файлов — 2,6 с вместе с запуском окружения компилятора (около 1 с). e2e без `nomos.json` в настоящем VS Code на папке только с `.kt` прошёл (2026-11-06): 12 находок, 4 файла с диагностиками, 11 CodeLens в `src/Estimates.kt`. Не проверено: CI на Ubuntu (шаг `--fetch` и сборка на Temurin 17); ответ настроек расширения Java; установленный `.vsix` руками; большой проект на Kotlin и Android-проект; размер `.vsix` с компилятором Kotlin.
