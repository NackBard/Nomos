# D-055. Этап 12: TypeScript и JavaScript

Ответы пользователя в начале этапа: модуль — файл; рёбра `type-only` равны `runtime` везде, кроме циклов; анализатор запускается на Node самого VS Code (`${node}`) со своим, зафиксированным компилятором TypeScript; программа строится по ближайшему `tsconfig.json`/`jsconfig.json`, без него — по всем файлам корня, объявления типов из `node_modules` читаются, если установлены. Проектное решение D-049 (один анализатор, две записи реестра, в manifest и facts язык один) подтверждено.

- **Анализатор `analyzers/typescript`** на TypeScript Compiler API, сам на TypeScript (стираемый синтаксис, `node src/main.ts` на Node 22.18 и новее). Язык выбирается первым аргументом: `main.ts [--language javascript] manifest | analyze …`, по умолчанию `typescript`. `manifest.name` у обоих — `nomos-typescript`. TypeScript читает `.ts .tsx .mts .cts` (без `.d.ts`), JavaScript — `.js .jsx .mjs .cjs` (без `.min.js`). Папки `node_modules`, `bower_components`, `dist`, `out`, `build`, `coverage` и скрытые не читаются: это зависимости и вывод сборки. Файлы другого языка того же проекта попадают в программу через разрешение импортов, но единиц не дают; ссылка на них — внешнее ребро с id по пути файла.
- **Новая зависимость:** `typescript` 5.9.2 — та же версия, что уже стоит в `ci`, `extension` и `conformance/runner`, поэтому установилась из локального кэша npm. Компилятор зафиксирован и едет в пакете: вывод не зависит от того, что установлено в проекте пользователя. Dev: `@types/node` 24.3.0.
- **Программа.** Файлы группируются по ближайшему `tsconfig.json` (для JavaScript сначала `jsconfig.json`), не выше корня. Из конфигурации берутся только опции (`paths`, `baseUrl`, `jsx`, `strict`…), набор файлов — все файлы языка под корнем: тесты и скрипты — тоже код. Без конфигурации — `strict`, `moduleResolution: bundler`, `allowJs`. Нечитаемый `tsconfig` — запись `diagnostics` с кодом `config-error` и опции по умолчанию.
- **Модуль — файл**, id — путь без расширения. Единицы, рёбра, фазы, оценки сложности и признаки парадигм описаны в `spec/metrics.md` (раздел «TypeScript и JavaScript») и `spec/paradigms.md`, строение типов — в `spec/structure.md`. Свободная функция — и `function`, и `const f = () => …`. Объявления в теле IIFE верхнего уровня считаются объявлениями модуля: иначе `extension/media/graph.js`, целиком обёрнутый в `(function () { … })()`, не давал ни одной единицы. Код верхнего уровня вне функций, `namespace` и `module.exports = function …` единиц не дают — это граница метода.
- **Вопрос 5 пересмотрен.** TypeScript — первый язык с `type-only`: аннотации, `implements`, интерфейсы и псевдонимы типов стираются, а импорт только ради типов компилятор удаляет. Для Ca, Ce, CBO и blast radius такие рёбра по-прежнему равны `runtime` (D-040): тип тоже связывает код. Циклы обоих уровней строятся только по `runtime`: цикл, замкнутый стёртой ссылкой, при выполнении не существует и не ломает порядок загрузки модулей. Правка `spec/metrics.md` общая, но в C# и Go все рёбра `runtime`, их вывод не меняется. Чтение поля объекта класса — `runtime` (код читает данные при выполнении), ссылка на интерфейс или псевдоним — всегда `type-only`. Импорт — `type-only` при `import type`, при именах только с `type` и при именах, которые используются только в позициях типов, если `verbatimModuleSyntax` и `preserveValueImports` выключены: так поступает компилятор. Линии графа фазу пока не показывают — расширение её не читает.
- **JavaScript.** Типы — вывод компилятора и JSDoc: `@param {(x: number) => number} f` даёт `hofOrder` 2, а `@param {Order} order` — `foreignMembers`. Ссылки внутри JSDoc рёбер не дают: `ts.forEachChild` в комментарии не заходит. CommonJS: `require("…")` — ребро `import`, а имя из `const { f } = require("…")` ведёт к функции или классу другого модуля через тип этого имени. Записи `needs-semantic-model`, задуманные в D-049 для правил по типам, не понадобились: ни одно поддержанное правило без типа не ломается, а детекторы по типу (ALG002: поиск по массиву, конкатенация строк) молчат, если тип не выведен.
- **Правила:** ALG001–ALG004, CC001–CC004, CC009, DSN001–DSN006, FUN005, MNT001–MNT004, OOP001–OOP005, PRN007, SEC001, SEC003, STR002, STR003 (30). STR001 — `not-supported` с сообщением «TypeScript has no goto»: в языке нет `goto`. Остальные (CC006–CC008, FUN001–FUN004, OOP006, PAT, PRN, SEC002) не написаны. Новые объяснения в spec с русским переводом: `ALG002.searchSet`, `frontInsertPush`, `concatJoin` (советы для массивов и строк JavaScript) и `ALG003.lambdaObject` (в JavaScript каждая лямбда — новый объект; незахватывающие не кешируются, как в C#). Методы строк (`replaceAll`, `split`…) в список линейных операций не входят: иначе `map` с `replaceAll` внутри давал «O(n²)» почти в каждой функции расширения.
- **Папка без файлов языка — пустой анализ с кодом 0** и записью `diagnostics` с кодом `no-files`, а не код 3, как у Go. Расширение выбирает анализатор по `**/*.js`, а этот шаблон находит файлы в `node_modules` проекта на C#: пользователь видел бы ошибку на ровном месте.
- **`${node}` в реестре** (`extension/src/core/bundle.ts`): подставляется `process.execPath`, и запуск получает `ELECTRON_RUN_AS_NODE=1` — так исполняемый файл VS Code ведёт себя как Node. Код от языка не зависит; это единственная правка `extension/src` за этап. Пакет (`scripts/package.mjs`): `tsc -p tsconfig.build.json` в `dist/`, результат — в `bundle/typescript/`, компилятор — `lib/typescript.js` с `lib.*.d.ts` рядом (там он ищет стандартную библиотеку) и `lib/package.json` с `"type": "commonjs"`. Импорт `typescript` переписывается на `./lib/typescript.js`, потому что `vsce` не пакует вложенные `node_modules`. Две записи реестра: `["${node}", "${bundle}/typescript/main.js"]` и то же с `--language javascript`. Пакет win32-x64 — 8,9 МБ вместо 6,6. `run-e2e.mjs` ставит среду в тестовый профиль только тем анализаторам, чьи файлы есть в папке: проекту на TypeScript не нужен .NET Install Tool.
- **Conformance.** Исходники TypeScript есть во всех 18 случаях, кроме `patterns` (исключение: правила PAT не написаны), эталоны посчитаны вручную. Случаи с аннотациями проверяют фазы: `coupling-martin` (импорт только ради типа — `type-only`), `cycles` (пара классов, связанных только типами, циклом не считается), `cycles-complex` (цикл модулей ping/pong без цикла единиц, которого у Go в этом случае не было). JavaScript — в 17 случаях. Его эталоны — эталоны TypeScript с правками для кода, который отличается (без аннотаций нет `type-only`, `#поля` вместо `private`, JSDoc, CommonJS в `cycles-complex` и `layers`); каждая правка расписана и сверена с исходником. Исключения JavaScript: `type-structure` (случай проверяет написанные типы, а в JavaScript их нет) и `patterns`. `parity` дописан для обоих языков, кроме `halsteadVolume` и `maintainabilityIndex`: аннотации TypeScript удлиняют сигнатуру (`add(a: number, b: number): number` — 47,5 против 28,1 у Go и 30,9 у C#), а у JavaScript без типов объём меньше (25,3); обе разницы шире допуска 15 %. В `coupling-martin` JavaScript сравнивается только по Ca, Ce и I: без абстрактных типов A домена равна 0, а не 0,5.
- **CI**: шаг «Analyzer TypeScript and JavaScript» (`npm ci`, `typecheck`, `test`) перед conformance; `npm run all` и новый `npm run typescript` в `conformance/runner`. `nomos.json` репозитория анализирует его собственный TypeScript (`analyzers/typescript`, `ci`, `extension/src`) и JavaScript (`extension/media`, `extension/scripts`).

Проверено: тесты анализатора (18: шаблоны текстов против spec, фазы импорта, цикл только по типам, CommonJS, JSDoc, IIFE, практики, детерминизм), harness для всех четырёх языков (`npm run all`: 83 из 83, parity между C#, Go, TypeScript и JavaScript), `dotnet test` (golden SARIF изменился только четырьмя новыми `messageStrings`), `go test`, тесты `ci` и harness, тесты расширения (37), `check-boundary`, `check-l10n`. Собранный анализатор выдаёт побайтно тот же facts, что исходники, и под Node, и под Electron VS Code (`ELECTRON_RUN_AS_NODE`, Node 24.22). e2e в настоящем VS Code на папке без `nomos.json` с файлами `.ts` и `.js` прошёл: оба встроенных анализатора запускаются через `${node}`, практики из настроек до них доходят, линзы метрик есть в `.ts`, диаграмма классов строится. e2e на этом репозитории с `nomos.json` прошёл на четырёх языках (C# 269, Go 218, TypeScript 320, JavaScript 53 находки); проверка диаграммы классов в e2e теперь берёт самый большой модуль, где есть типы: самый большой JavaScript-модуль репозитория, `graph.js`, написан функциями. `ci` на этом репозитории — 26 с на четырёх языках. Не проверено: установленный `.vsix` руками в VS Code и большой проект на TypeScript (тысячи файлов).
