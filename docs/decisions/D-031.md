**Id правил.** Детектор именования теперь сразу `CS.NAM001`; отображение `RuleIds` и параметр `FactsOptions.RuleId` удалены, фикстура переехала в `tests/fixtures/csharp/oop/CS.NAM001`. Тест сверяет id всех детекторов со `spec/rules`.

**Удалено.** `Nomos.Cli` и его тесты, `Nomos.Languages.TreeSitter`, `PluginLoader`, настройка `PluginsPath`, `JsonReportWriter`, старый `SarifReportWriter`, golden `expected.{json,md,sarif}`. Команды `list-analyzers` и `init` заменены: первая — `manifest`, вторая не нужна, файл рабочей области пишется руками.

**Reporting.** `MarkdownReportWriter` и `HtmlReportWriter` оставлены: этап 8 строит отчёты «по образцу прежнего Reporting» (открытый вопрос 2 не закрыт). К анализатору они не подключены, живут только с юнит-тестами; golden для md удалён.

**Golden.** Новые `expected.facts.json` и `expected.sarif` снимаются запуском `nomos-csharp` как процесса (`tests/Nomos.Analyzer.Tests`); эти же тесты проверяют коды возврата 0, 2, 3. Это снимки для отслеживания изменений, а не эталоны conformance: те по-прежнему считаются вручную.

**Коллизия `nomos.json` (D-024, D-027) закрыта.** `--config` принимает только файл рабочей области (`contracts/nomos.schema.json`); `WorkspaceFile` переводит его в `NomosConfig`: `rules`, `paradigms`, `layers`, `scoring` и `include`/`exclude` записи своего языка. Файл с другой мажорной версией — код 3. `analyzers/csharp/nomos.json` удалён, корневой `nomos.json` стал файлом рабочей области этого репозитория с настройками самоанализа. Цена: подавления по путям (`suppressions`) и выключение категорий есть в движке, но в контракте их нет, поэтому через протокол они недоступны. Расширять контракт ради этого не стал: это открытый вопрос 10. Директивы `nomos-disable` и `[NomosSuppress]` работают. Фикстуры анализаторов сохранили формат `NomosConfig`, он теперь внутренний.

**`--rules`** реализован (раньше принимался и игнорировался): запускаются только перечисленные правила, неизвестный id — код 2. Несуществующий `--config` — код 3, а не 1.
