# D-029. Одни метрики для facts и для анализаторов; `kind` рёбер; `measured`; тексты правил из spec

**Метрики в одном месте.** Анализаторы считали DIT, CBO, LCOM4, ATFD, TCC, WMC и метрики Мартина по-своему, а facts — по `spec/metrics.md`, так что число в находке могло не совпасть с числом в facts. Теперь функции по spec лежат в `TypeMetrics` (Abstractions) и в `DependencyGraphs` (Graph); facts и анализаторы OOP002, OOP004, OOP005, DSN001, DSN004 вызывают одни и те же. Следствия: Ce считает различные внешние типы, а не зависящие типы модуля; у изолированного модуля нет instability и distance (`null`); LCOM4 и TCC дают `null` вместо 0 и 1 там, где метрика не определена; WMC не включает аксессоры; DIT считает внешнюю базу одним шагом; CBO исключает стандартную библиотеку по префиксам `System.`/`Microsoft.`, а не по строке `System*`. Golden-файлы старого CLI перегенерированы: меняются только значения этих метрик. В facts добавлены `atfd` и `tcc`. Уточнения в spec: ATFD — только проектные типы, TCC — видимые методы определены, WMC — методы и конструкторы.

**Виды рёбер** определены в `spec/metrics.md` («Виды рёбер зависимостей»): `inheritance`, `call`, `type-ref`, `import`. Harness теперь сравнивает `kind`; прежняя оговорка из D-026 снята. Все ручные эталоны уже соответствовали определению.

**`properties.measured`.** В `Finding` добавлено необязательное поле `Measured` (`Measurement`: метрика, значение, порог), `AnalysisContext.Report` принимает его. Заполнено для правил, у которых значение совпадает с метрикой facts: CC001, CC002 (по строкам), CC003, CC004, MNT001, OOP002, OOP004, OOP005, DSN001, DSN004 (WMC), DSN006. Для остальных правил с порогами (около двадцати: ALG, PRN, STR, PAT и др.) поле пока пусто; они дорабатываются по одному. Harness проверяет форму поля и что значение совпадает с метрикой сущности (или модуля) в facts.

**Тексты правил.** `spec/rules/*.yaml` встраиваются в сборку `nomos-csharp` (EmbeddedResource) и читаются YamlDotNet 16.3.0 (новая зависимость; нужна только `Nomos.Analyzer.CSharp`). `driver.rules[]` в SARIF: `name` — title, `shortDescription` — description, `fullDescription` — rationale, как требует профиль. Harness сверяет эти тексты со spec. Собственные `Description` в атрибутах анализаторов остаются для старого CLI.

**Схема SARIF.** Официальная схема OASIS (draft-04) не копируется в репозиторий — у файла нет явной лицензии на распространение. `npm run fetch-sarif-schema` скачивает её в игнорируемую `conformance/runner/.cache`; если файл есть, harness валидирует по нему (пакет `ajv-draft-04` 1.0.0, новая зависимость harness), иначе печатает напоминание. Схема проверена на заведомо неверном файле.
