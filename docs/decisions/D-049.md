# D-049. План после выпуска: практики, русский язык, диаграмма классов, шесть новых языков

Пользователь попросил четыре функции и разрешил самому расставить этапы. Смысл трёх уточнён у него:

- **«Модель для выбора практик»** — профиль практик, который пользователь отмечает сам: именованные наборы правил из spec. Не подсказка по коду и не языковая модель: вывод остаётся детерминированным, внешних служб нет.
- **«Русский язык»** — интерфейс расширения, отчёты `ci`, тексты правил и находок. Не разбор кириллических идентификаторов.
- **«UML»** — диаграмма классов. Диаграммы пакетов и последовательности отложены и записаны в ROADMAP, раздел «Отложено».

**Этапы.** 10 — профиль практик, 11 — русский язык, 12 — диаграмма классов, 13–18 — TypeScript и JavaScript, Python, Java, Kotlin, Ruby, C++. Этап 9 (выпуск) остаётся текущим. Почему так:

- Этапы 10–12 меняют контракты (`nomos` 1.1.0, `rule` 1.1.0, профиль SARIF, facts 1.3.0). Если сделать их до языков, каждый новый анализатор реализует их сразу, а дорабатывать придётся только C# и Go.
- Практики раньше перевода: они добавляют строки интерфейса, которые этап 11 переведёт вместе с остальными. После этапа 11 строка без русского текста не проходит `check-l10n`, поэтому интерфейс диаграммы классов пишется сразу на двух языках.
- Языки — по отношению аудитории к стоимости. TypeScript и JavaScript работают на Node самого VS Code и не требуют от пользователя своей среды. Python и Java — большие аудитории со зрелыми родными средствами. Kotlin идёт после Java, потому что делит с ним JVM. Ruby — меньшая аудитория. C++ последний: препроцессор, флаги сборки и нативный анализатор под каждую платформу.

**Проектные решения в плане**, подтверждаются в начале своего этапа:

- Правило, выключенное выбором практик, получает в `skippedRules` существующую причину `disabled-by-config`, а не новую: новое значение перечисления — мажорная версия facts. Сообщение называет практики.
- Переводы находок — через `message.id`, `message.arguments` и `rule.messageStrings` из SARIF 2.1.0, с шаблонами в spec. Анализатор не знает локали, поэтому вывод одинаков при любом языке интерфейса; `message.text` остаётся английским запасным вариантом.
- Связи UML не требуют нового вида рёбер: обобщение и реализация различаются по `kind` и `isAbstract` цели ребра `inheritance`, ассоциации — по новым членам типов. Новый вид в перечислении `dependencies[].kind` был бы мажорной версией.
- Один анализатор на TypeScript и JavaScript, но два языка в реестре: в manifest и facts язык один.

Открытые вопросы 11–15 добавлены в список выше. Код и контракты этой записью не менялись.
