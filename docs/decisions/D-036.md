# D-036. Этап 5: оценки сложности в facts, `config` в случаях, `missing-input`, blast radius за один проход

**Оценки — общая функция.** `spec/metrics.md` теперь определяет `timeDegree`, `timeLogFactor`, `timeExponential`, `spaceDegree`, `allocationDepth`, `foreignMembers`, `ownMembers`; все выводятся в `functions[].metrics` независимо от порогов. Схема facts не менялась: дополнительные метрики функции она разрешает. `Estimator` перенесён из `Nomos.Analyzers.Algorithms` в `Nomos.Abstractions/Ir/Complexity.cs` (`ComplexityEstimates`), потому что `Nomos.Facts` не ссылается на детекторы.

У экспоненциальной оценки нет степени, поэтому `timeDegree` там `null`, а отдельное `timeExponential` отличает её от функции без тела. Прежний условный код 99 не годился: он выглядел бы как измерение. Функции оцениваются в порядке Ordinal по id: взаимная рекурсия обрывается на функции, которая ещё считается, и при другом порядке facts и находка разошлись бы. Список линейных операций языко-зависим и принадлежит анализатору, spec задаёт только смысл; случай `complexity-estimates` от него не зависит и взаимной рекурсии не содержит.

**`measured`.** Заполнено у ALG001, ALG003 (кроме материализации в цикле, у которой нет порога), ALG004, DSN005. Harness сверяет значение `measured` с метрикой сущности, поэтому находка ALG003 несёт `allocationDepth` функции, то есть наибольшую глубину, а не глубину своего места. На самоанализе `measured` есть у 237 из 281 результата (было 82 из 272, D-030). Без него остаются правила без порога ALG002 и DSN002, материализация в ALG003.

**Контракт `conformance-case` 1.1.0** (минорная версия: необязательное поле). `config: true` означает, что рядом лежит `nomos.json`, который harness передаёт как `--config`; `validate` проверяет его по схеме. Имя и расположение заданы условно, как у `expected.sarif.json`. Поле `schemaVersion` стало `enum`, старые случаи остаются 1.0.0. Заодно уточнён смысл `expectSarif`, который раньше ни разу не использовался: сравниваются только правила из `covers`, иначе в каждый эталон пришлось бы вписывать находки всех прочих правил. Запись эталона может содержать `measured`.

**`missing-input`.** `rule.schema.json` требует эту запись для `requires`, но DSN003 без `layers` и MNT004 без отчёта молча ничего не делали. Теперь `SpecRules` читает `requires`, `Program` определяет доступные входы, facts пишут запись на весь запуск, harness проверяет её в обе стороны. Golden получил запись у MNT004.

**Найдено случаями и исправлено.** Шаблон слоя искал первое вхождение последней части: `*.Domain` не подходил к `App.Domain.Domain`, и нарушения такого модуля терялись. Шаблон теперь регулярное выражение на всю строку; правила сопоставления записаны в `spec/metrics.md`, раздел «Слои», а не в описании схемы `nomos`, чтобы не менять контракт ради текста. В остальном детекторы совпали с ручными эталонами с первого запуска; единственное расхождение (строка `new Box()` в `complexity-estimates`) оказалось ошибкой подсчёта в эталоне и исправлено там, по тексту файла.

**Blast radius.** `BlastRadius.Counts` считает все значения за один проход по конденсации графа (битовые множества, по биту на пару компонента — вершина), значения совпадают с обходом на случайных графах (тест). `facts` раньше обходил граф и на каждый тип, и на каждую функцию. На сгенерированном проекте из 3000 типов и 11 816 рёбер, где почти всё зависит от почти всего, полный запуск занял 8,3 с против 9,0 с, значения те же: на таком размере это не было узким местом, основное время идёт на компиляцию Roslyn. Выигрыш важен лишь на бо́льших графах; замеров больше 3000 типов нет. Память квадратична по числу типов: около 1 МБ на 3000, 125 МБ на 30 000.

**Не менялось.** `DSN002` по-прежнему не сообщает о цикле типа с вложенными в него типами, facts его показывают; расхождение намеренное, в случаях не проверено. Parity по-прежнему не проверяется: все случаи только на C# (D-026).
