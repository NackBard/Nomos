# D-061. Этап 16: Ruby

Ответы пользователя в начале этапа (2026-11-07), закрывают открытый вопрос 12 для Ruby: минимальная версия — Ruby 3.3, разбор — Prism из стандартной библиотеки; интерпретатор — `ruby` из `PATH` (RubyInstaller на Windows, шимы rbenv, asdf, mise на Unix): Ruby LSP не отдаёт путь к интерпретатору командой, своей настройки у Nomos нет, `extension/` меняется только реестром; без подходящего Ruby — сообщение с причиной и кнопкой страницы установки, остальные анализаторы работают. Модуль — пространство констант (`module A::B`), верхний уровень — `(global)`, как пакеты Java и Kotlin; класс, переоткрытый в нескольких файлах, — один тип; зависимости — по ссылкам на константы, а не по `require`. `include` и `prepend` — ребро `inheritance` (модуль встаёт в цепочку предков; в UML — реализация, модуль — абстрактная цель), `extend` — ребро `type-ref`: он меняет только синглтон объекта. Граница метапрограммирования: `attr_reader`, `attr_writer`, `attr_accessor` — поля с аксессорами; `define_method`, `method_missing`, `send`, `instance_variable_get`, `eval` не разрешаются и рёбер не дают; `manifest.capabilities.semantic` и `facts.analyzer.semantic` — `false`, как у Python и Kotlin. Проектные решения D-049 (`disabled-by-config`, `message.id` с шаблонами spec и английским `message.text`, UML без новых видов рёбер) подтверждены для Ruby.

- **Анализатор `analyzers/ruby`** на самом Ruby, только стандартная библиотека: Prism (`Prism.parse` для дерева, `Prism.lex` для токенов и комментариев), `json`, `digest`. Запуск — `ruby --disable-gems main.rb`: гемы окружения пользователя не загружаются, как `python -I`, и Prism берётся тот, что пришёл с Ruby. Новых зависимостей нет. Prism в Ruby 3.3 — версия 0.19, в 3.4 и новее — 1.x с переименованными полями (`consequent` → `subsequent`, `child` → `name` у пути константы, `operator` → `binary_operator`); чтение этих полей собрано в `Compat` (`lib/nomos_ruby/support.rb`). Код проверен на Ruby 3.3.13 (Prism 0.19.0); на Prism 1.x не запускался.
- **Модуль и типы.** Модуль Nomos — только пространство имён. Миксин (`module` с экземплярным методом не под `module_function` и без `extend self`) — тип вида `trait`, а не модуль: иначе id модуля и id типа совпали бы, а расширение (`buildGraph` в `extension/src/core/views.ts`) принимает id, равный id модуля, за модуль. Вид `trait` уже есть в расширении — реализация в UML и перевод «трейт», — поэтому `extension/` не меняется. `def self.x` и `module_function` в пространстве имён — функции модуля (id `Shop.x`), как функции верхнего уровня Kotlin; методы — `Тип#имя` и `Тип.имя` (нотация Ruby). Файл относится к самому глубокому пространству, в котором лежит всё, что он объявляет: модуль может собираться из многих файлов, а `loc` не считается дважды. Компактная форма `class A::B` имеет лексическую вложенность только `A::B`, как в Ruby: константы внутри неё ищутся полным путём.
- **Типы значений из YARD.** Без объявленных типов параметров «зависть к чужим данным», ATFD и вызовы на параметрах не видны. Как для JavaScript берётся JSDoc (D-055), для Ruby берутся теги YARD — стандартная документация типов в Ruby: `@param имя [Тип]` (и `@param [Тип] имя`), `@return [Тип]` над методом и над `attr_*`. Они дают тип значения, `typeName` и `returnTypeName`, но не рёбра. Без тега тип известен из `X.new`, литералов и последнего выражения метода.
- **Изменяемость.** Переменная экземпляра изменяемая, если ей присваивают вне `initialize` или составным присваиванием; свойство — при `writer`/`accessor`. Так объект-значение с `attr_reader` даёт `fp.immutable-types`, как `val` в Kotlin. `Struct.new` и `Data.define` — записи: для `foreignMembers` не считаются (ATFD учитывает), как data-классы Kotlin.
- **Циклы — итерация блоком.** `each`, `times`, `upto`, `loop` и другие методы обхода с блоком — точки решения, уровни вложенности и множители оценки времени: циклы в Ruby пишут так. Поэтому `metrics-basic`, `complexity-estimates` и `design-smells` дают те же числа, что у других языков, и Ruby вписан в их `parity`. `map`, `select` и подобные — линейные операции, а не циклы, как у Kotlin.
- **Правила** — 29: те же, что у Python, без OOP001 (`not-supported`: переменные экземпляра всегда закрыты); STR001 — «Ruby has no goto». Переменная класса `@@x`, которой присваивают в методе, — STR002 при любой видимости: это общее состояние иерархии классов. Новых шаблонов в spec нет; `npm run spec-json` пишет `lib/nomos_ruby/rules.json` и `practices.json`.
- **Скорость.** На стандартной библиотеке Ruby 3.3 (861 файл, 1564 типа, 12 724 функции, 667 тыс. токенов) анализ занял 29 с. По дороге найдено и исправлено: хеш `Struct` считается по значению всех полей, поэтому файл (`SourceFile`) стал ключом по идентичности (SEC001 — с 42 до 0,9 с); Halstead — по индексу токенов файла по строкам (MNT002 — с 14 до 0,6 с); поиск клонов в повторяющихся таблицах сравнивал одно и то же для каждого прежнего места того же файла — теперь для расстояния запоминается отрезок, где последовательность повторяется с этим периодом (MNT003 — с 139 до 1,5 с). Результат поиска клонов совпадает с прямым перебором на шести каталогах стандартной библиотеки (до 831 находки) и в тесте.
- **Поставка.** `extension/scripts/package.mjs` кладёт `main.rb` и `lib/nomos_ruby/` в `bundle/ruby/`, файлы одни на все платформы. Запись реестра: `["${runtime}", "--disable-gems", "${bundle}/ruby/main.rb"]`, `runtime` с `path: ["ruby"]`, проверкой — запуском `manifest` (Ruby старше 3.3 и Ruby без Prism её не проходят) и `installUrl` ruby-lang.org. `extension/` изменился только в `scripts/package.mjs` (реестр) и в `scripts/check-boundary.mjs` (имена `ruby`, `prism` и расширение `.rb` теперь тоже запрещены в коде расширения).
- **Запуск в репозитории.** `node analyzers/ruby/run.mjs` ищет `$NOMOS_RUBY`, затем `ruby` из `PATH`; `--test` запускает тесты тем же Ruby. `nomos.json`, `npm run ruby` и `npm run all` запускают его. CI ставит Ruby 3.3 действием `ruby/setup-ruby@v1` (без bundler) — действие организации Ruby; другого способа получить Ruby 3.3 на Ubuntu нет (в образе — другая версия).
- **Conformance.** Ruby есть во всех 19 случаях, кроме `patterns` (исключение: правила PAT не написаны); эталоны посчитаны вручную. `parity` дописан в `metrics-basic`, `blast-radius`, `complexity-estimates`, `coupling-martin`, `design-smells`, `oop-cohesion`; Halstead и MI в `maintainability` — нет: у Ruby свои токены (`def add(a, b)` — 7 токенов без разделителей). Отличия формы: зависимость без типов полей — ленивое создание (`@prev ||= C1.new`, ребро `call`) или метод, возвращающий константу (`def out = B::B1`, `type-ref`); типы параметров в `design-smells` — из YARD, `Money` — `Data.define`, у `God` закрытые `attr_reader` вместо полей; в `oop-cohesion` поля `@a`, `@b` — ленивые (`@a.to_i`), чтобы не было `initialize` и WMC совпал; «перечисление» `paradigm-evidence` — модуль из констант (пространство имён без признаков); `Box` в `health` объявлен компактно `class Health::Tiny::Box`; функции `suppressions` и `maintainability` — `def` верхнего уровня, модуль `(global)`.

Проверено: тесты анализатора (16: шаблоны текстов против spec, manifest, `elsif` и вложенный `else if`, `include`/`prepend`/`extend` и компактный путь, переоткрытый класс, функции модулей, типы YARD без рёбер, строка с подстановкой и heredoc одним токеном, глобальное состояние, практики, коды возврата, пустая папка, файл в US-ASCII, детерминизм, поиск клонов против прямого перебора), `npm run ruby` — 26 из 26, `npm run all` — 159 из 159 на восьми языках с `parity`, `npm run validate`, тесты harness и `selftest`, `dotnet test` (golden не изменился), `go test`, тесты Python, `ci` и расширения (43), `check-boundary`, `check-l10n`, `npm run package -- --bundle-only`. Анализ стандартной библиотеки Ruby детерминирован (два запуска побайтово равны). e2e без `nomos.json` в настоящем VS Code на папке только с `.rb` прошёл (2026-11-07): 12 находок, 4 файла с диагностиками, 11 CodeLens в `lib/estimates.rb`.
