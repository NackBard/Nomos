# D-023. Принятые мной решения при написании контрактов

- `schemaVersion` — строка semver, начальное значение `"1.0.0"`, проверяется как `const` в каждой схеме. Версия схемы также лежит в `$id` и в `x-contractVersion`.
- Связь «runtime или type-only» вынесена в отдельное поле `phase`, а `kind` ограничен значениями `import`, `inheritance`, `call`, `type-ref`: так одна и та же связь классифицируется по двум независимым осям.
- Идентификаторы сущностей — родные квалифицированные имена языка, стабильные между запусками; сопоставление между языками идёт через `parity` в `case.json`, а не через единые id.
- Языко-специфичное правило получает префикс с кодом языка, формат `CS.NAM001`. Прежнее правило `CC005` переименовано в `CS.NAM001`, поскольку проверяет конвенции именования .NET.
- Активация парадигмы по признакам задана в `spec/paradigms.md`: `oop` — наличие классов, `functional` — функции высшего порядка или чистые функции или не менее трёх лямбд, `structural` — свободные функции или ветвления. Порог «три лямбды» — эвристика, чтобы LINQ не включал функциональный профиль на обычном C# (продолжение D-011).
- Метрики графа (Ca, Ce, циклы, blast radius) считаются над единицами «тип или свободная функция», все виды рёбер и обе фазы равноправны, рёбра на внешние цели не участвуют. Дальнейшее уточнение (учитывать ли `type-only` отдельно) — открытый вопрос.
- Вложенные функции и лямбды входят в сложность охватывающей функции.
- Harness conformance предлагается писать на TypeScript/Node: те же инструменты нужны расширению, там есть зрелые валидаторы JSON Schema.
- Имя продукта — Nomos (D-024); файл рабочей области — `nomos.json`.
