# D-038. Этап 7: второй язык — Go

Закрывает открытый вопрос 7, язык выбрал пользователь. Анализатор — `analyzers/go`, `go/parser`, `go/scanner`, `go/types`; зависимостей вне стандартной библиотеки нет. Импорты стандартной библиотеки разрешаются importer'ом `source`, поэтому нужен Go на машине запуска; если он не сработал, `analyzer.semantic` равно `false` и есть диагностика `no-stdlib`. Сторонние пакеты не разрешаются, для них работает то, что видно по синтаксису. Тесты (`_test.go`), `vendor` и `testdata` не анализируются.

**Модуль** — пакет, id — путь импорта от ближайшего `go.mod` (в репозитории их может быть несколько). Закрывает открытый вопрос 4 практикой: единицы — и типы, и свободные функции; Go показал, что это работает, модуль как единственная единица не нужен. Открытый вопрос 5 остаётся: `type-only` в Go нет.

**Соответствия** записаны в `spec/metrics.md` («Языки без классов») и `spec/paradigms.md`. Самое спорное: встраивание считается `inheritance`, хотя в языке это композиция с продвижением членов, иначе у DIT и `oop.inheritance` не было бы входа. Неявная реализация интерфейса ребра не даёт: она не написана в объявлении, а граф строится по написанному. Поэтому в `coupling-martin` для совпадения чисел `SqlRepo` встраивает интерфейс.

**Правила.** 28 из 62 правил `spec/rules` без префикса. Не реализованы PAT (классы, конструкторы, свойства, события), SEC002 (в стандартной библиотеке нет форматтеров, создающих произвольные типы), OOP001 и OOP006, CC006–CC009, PRN001–PRN009, FUN001–FUN004. Часть из них выразима в Go и просто не написана: CC006–CC009, FUN001–FUN004, часть PRN. Все записаны как `not-supported`. По умолчанию `functional` выключен, как у C# (D-011).

**Тексты правил.** `go:embed` не выходит за пределы модуля, а зависимость ради YAML не нужна, поэтому `internal/analyzer/rules.json` генерируется из `spec/rules` (`npm run go-rules`) и лежит в репозитории; `validate` падает, если он устарел.

**Контракт `conformance-case` 1.2.0** (минорная версия). Поле `exceptions` с языком и причиной; его предлагал README и D-026. Harness теперь считает ошибкой случай без исходников языка и без записи, иначе новый язык мог бы молча пропускать случаи. Единственное исключение — `patterns`.

**Parity** проверяется в семи случаях: `metrics-basic`, `coupling-martin`, `oop-cohesion`, `blast-radius`, `complexity-estimates`, `design-smells`, `maintainability`. Запускает его `npm run all`, он же теперь в CI. Это первая настоящая проверка conformance между языками (D-026).

**Что показала проверка.** Анализатор прошёл почти все случаи с первого запуска: единственное расхождение (`loc` в `funcs.go`) — ошибка подсчёта в моём эталоне. Но это слабее, чем кажется: анализатор и эталоны писал один автор по одной спецификации, а `complexity-estimates` не проверяет линейные вызовы и взаимную рекурсию. Определения spec оказались достаточно точными для цикломатики, связности, blast radius и оценок сложности. Halstead на одной функции разошёлся на 9 % (30,88 против 28,07): порядок один, допуск 15 % нужен, что отвечает на открытый вопрос 8: оставить с допуском.

**`EXTENDING.md` проверен на практике**, исправлено: протокол без `--config` и `--rules`; метрике не нужно расширение схемы; пример `cwd` ломал бы путь SARIF; описан путь текстов правил и `exceptions`.

**Рабочая область.** В корне появился `go.work`, чтобы `go run nomos/analyzers/go/cmd/nomos-go` работал из корня: расширение запускает команду из папки `nomos.json`, а путь SARIF относителен ей.

**Границы.** Подавлений (`nomos-disable`) в Go нет: открытый вопрос 10 по-прежнему не решён, а общего контракта для них нет. Blast radius здесь считается обходом на единицу: проекты Go такого размера, как в D-036, не проверялись. Правило CC002 считает структуру и методы, но `lines` у типа — только его объявление, потому что методы лежат вне него.
