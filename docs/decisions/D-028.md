# D-028. Слой facts и SARIF для C#, протокол `manifest`/`analyze`

Шаг 2 миграции (этап 2). Новые проекты в `analyzers/csharp/src`:

- `Nomos.Facts` — строит facts по IR и пишет SARIF по `contracts/sarif-profile.md`. Метрики считаются по `spec/metrics.md` заново, а не берутся из IR-помощников там, где определения расходятся: Ce считает различные внешние единицы, а не типы модуля; изолированный модуль даёт `instability = null`, а не 0; DIT считает внешнюю базу одним шагом и не идёт вверх по её предкам; LCOM4 без экземплярных методов равен `null`; самопетли отбрасываются и в графах, и в списке `dependencies`.
- `Nomos.Analyzer.CSharp` (`nomos-csharp`) — программа с командами `manifest` и `analyze --root [--sarif] [--config]`. Файл `nomos.json` в корне анализируемого проекта не читается: он означает файл рабочей области (D-024); конфиг задаётся только `--config`. Заменит `Nomos.Cli` на шаге 4; до тех пор оба живут рядом.
- Движок отдаёт IR в `AnalysisResult.Model` (необязательное свойство; прежние писатели его не используют, golden-файлы не менялись из-за него).

**Договорённости по facts.**

- Id типа — метаданные-имя (`Shop.Domain.IRepo`). Id функции — `Тип.Имя`; для перегрузок остаётся полный id IR с типами параметров (`A.X.Run(System.Int32)`), чтобы id были уникальны. Аксессоры и локальные функции в `functions` не выводятся (входят в владельца, как лямбды в spec); неявные конструкторы IR не создаёт.
- `dependencies.kind`: наследование и реализация интерфейса — `inheritance`, создание и вызов — `call`, прочее — `type-ref`. Фаза всегда `runtime` (в C# нет аналога `type-only`). Внешняя цель без `stdlib`, если её id не начинается с `System.`/`Microsoft.`.
- `loc` файла — число строк с хотя бы одним токеном не-комментарием, `lines` — физические строки; `loc` модуля — сумма по его файлам.
- Признаки парадигм: `oop.*` (4 вида), `str.free-functions`, `str.control-flow`, `str.global-state`, `fp.lambdas`, `fp.higher-order`. Не собираются `fp.pure-functions` и `fp.immutable-types` (нет проверяемого определения). Метрики типа `atfd` и `tcc` пока не выводятся: определения IR (`TCC = 1` при одном методе) расходятся со spec, переход отложен.
- `skippedRules`: правило с парадигмой записывается как `paradigm-not-detected` для каждого модуля, где нет признака активации ни одной из его парадигм. Сам движок пока запускает правила по языку, а не по модулю; это расхождение с `spec/paradigms.md` остаётся и закроется переносом решения в движок.
- Идентификаторы правил: `CC005` выводится как `CS.NAM001` на границе протокола (манифест, facts, SARIF); класс и golden старого CLI остаются прежними до шага 3. `DSN004` и `DSN005` получили парадигму `oop` по spec (ранее «любая»); фикстуры перенесены из `universal` в `oop`.
- Цикломатическая сложность больше не считает `??`: spec перечисляет только `&&`, `||`, `and`, `or`.

**SARIF.** Отдельный `SarifProfileWriter`, старый `SarifReportWriter` не тронут (нужен прежнему CLI и его golden). Расхождения профиля и прежнего писателя устранены: `message` без объяснения, `properties.explanation`, `confidence` строчными, `level` по таблице профиля, `entity` вместо `symbol` с id из facts, все поддерживаемые правила в `driver.rules`, сортировка после замены id.

**Harness.** Добавлены проверки: парадигмы и категория каждого правила манифеста равны spec; SARIF по профилю (поля, уровни, сортировка, пути, `entity` существует в facts, `checks.sarifFile`/`resultCount`); детерминизм и SARIF-файла. Официальная схема SARIF 2.1.0 в репозитории отсутствует, поэтому проверяется только профиль.

**Не закрыто.** `driver.rules[].fullDescription` должно быть `rationale` из `spec/rules`, а анализатор знает только `description`: нужно решить, откуда он берёт `rationale` (встраивание данных spec при сборке или поле в атрибуте правила). `properties.measured` не выводится: у находки нет поля для измеренного значения и порога. `parsed: false` и код возврата 4 (случай `partial-failure`) не реализованы. Blast radius считается обходом на каждый тип (квадратично), для больших проектов потребуется один проход.
