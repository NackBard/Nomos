# D-051. Этап 9: профиль практик

Ответы пользователя в начале этапа: практики нарезаются по темам, а не по категориям spec, и выбирают только находки.

- **Каталог** — `spec/practices.yaml` по новому контракту `practice` 1.0.0: id, название, описание, правила. Одиннадцать практик: `solid`, `simplicity` (DRY, KISS, YAGNI, Деметра), `clean-code`, `oop`, `functional`, `structural`, `architecture`, `maintainability`, `performance`, `patterns`, `security`. Правило может входить в несколько практик: God class и Feature envy (DSN004, DSN005) — и в `architecture`, и в `oop`. В отличие от плана D-049, практика перечисляет правила явно, без ссылок на категории: иначе разворачивать категории пришлось бы в C#, Go и расширении. Цена — новое правило нужно вписать в практику руками, поэтому `npm run validate` требует, чтобы каждое правило входило хотя бы в одну практику и каждый id существовал.
- **`nomos.json` 1.1.0: необязательное `practices`.** Нет поля — работают все правила, как раньше. Пустой список — не работает ни одно. Явное `rules.<id>.enabled` сильнее практики в обе стороны. Незнакомая практика — ошибка входа, код 3.
- **Пропуск — `disabled-by-config`** на весь запуск, с сообщением «Rule belongs to practice clean-code, which is not selected; 'practices' in nomos.json selects them», одинаковым в C# и Go. Новая причина потребовала бы мажорной версии facts. Если правило выключено ещё и парадигмой или `--rules`, запись одна, с прежним сообщением.
- **Метрики и балл.** Facts, граф и CodeLens от практик не зависят. Балл, как и раньше, считается по категориям правил, которые запускались: категория, все правила которой выключены практиками, в балл не входит. Отдельной логики для практик в балле нет.
- **Каталог в анализаторах и расширении.** C# встраивает `spec/practices.yaml` (`SpecPractices.cs`). Go и расширение получают JSON из нового `npm run spec-json` (`go-rules` оставлен тем же скриптом): `analyzers/go/internal/analyzer/practices.json` и `extension/practices.json`. `npm run validate` сверяет все созданные из spec файлы.
- **Расширение.** Команда «Nomos: Choose Practices» (значок в заголовке дерева находок) показывает каталог с галочками. В папке с `nomos.json` выбор после подтверждения записывается в его `practices`: файл переписывается с отступом в два пробела, версия 1.0.0 поднимается до 1.1.0. В папке без `nomos.json` выбор идёт в настройку `nomos.practices` папки (D-050). Тогда расширение пишет в своё хранилище файл рабочей области (`workspaces/<хеш папки>-<язык>.json`, команда анализатора и `practices`) и передаёт его через `--config`. Выбор всех практик сохраняется как отсутствие поля, чтобы практики следующих версий тоже были включены. Изменение настройки запускает анализ, подсказка строки состояния называет практики каждой папки.
- **Harness.** Правило, выключенное конфигурацией, больше не обязано иметь запись `missing-input`: оно не запускается, и вход ему не нужен. Раньше это не проявлялось, потому что ни один случай не выключал DSN003 или MNT004.
- **Случай `practices`**: выбрана `security`, SEC001 выключено явно, на обоих языках. SEC003 сообщает, SEC001 и CC003 молчат, хотя пароль в коде и шесть параметров есть. CC003, DSN001 и SEC001 записаны как `disabled-by-config`.
