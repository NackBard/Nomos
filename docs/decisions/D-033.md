# D-033. Лямбды не активируют функциональную парадигму; парадигму нельзя объявить явно

Закрывает открытый вопрос 6, заменяет порог «три лямбды» из D-023. Решение принял пользователь.

**Активация.** `fp.lambdas` записывается в facts как статистика, но `functional` активируют только `fp.higher-order` и `fp.pure-functions`. На самоанализе Nomos (обычный объектный код с LINQ) прежнее правило активировало парадигму в 16 модулях из 16 и ничего не различало; новое — в 7 из 16. Порог на плотность отвергнут: это ещё одно подбираемое число, а на LINQ-коде плотность всё равно высока. Парадигма по-прежнему активируется одной функцией с признаком; порог на их долю можно ввести позже, если этого окажется мало.

**Объявление.** Явного объявления парадигмы нет ни в `nomos.json`, ни в коде: конфигурация только отключает парадигму для языка (`spec/paradigms.md`), контракт не меняется. Иначе правила ООП могли бы сработать на модуле без классов. К вопросу можно вернуться, когда появится реальный случай.

Новых golden-файлов и эталонов не потребовалось: functional для C# выключен по умолчанию (D-011), а случаи conformance этого условия не задевали. Условие закреплено юнит-тестом в `Nomos.Facts.Tests`.
