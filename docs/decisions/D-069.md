# D-069. Только доверенная папка; закрепление CI

Просьба пользователя (2026-11-15), после разбора безопасности 2026-11-14.

## Расширения

Ядро запускает то, что написано в `nomos.json` (`command`, `cwd`, `env`), и программы, найденные по настройкам рабочей области (D-057), а включается само по `workspaceContains:nomos.json`. Чужой репозиторий с таким файлом — запуск чужой команды при открытии папки. От этого защищало только умолчание VS Code для расширений без `capabilities.untrustedWorkspaces`.

Решение:

- ядро, Score и Agents объявляют `capabilities.untrustedWorkspaces.supported: false` с объяснением и `virtualWorkspaces: false` (им нужны файлы на диске); VS Code держит их выключенными в Restricted Mode и включает, когда человек доверит папку;
- на случай вызова в обход этого `analyzeAll` ядра и `core()` агентов проверяют `vscode.workspace.isTrusted` и ничего не запускают в недоверенной папке.

Почему не `supported: "limited"` с одними анализаторами пакетов: ради этого режима пришлось бы делить настройки и среды выполнения на безопасные и нет, а польза мала — анализ чужой папки без доверия редкий случай, и VS Code сам предлагает доверить её.

## Agents и MCP-сервер

- `git` вызывается с `-c core.fsmonitor=false` (иначе `.git/config` папки называет программу, которую git запустит сам) и `diff` — с `--no-ext-diff --no-textconv`; база, которая начинается с `-`, отвергается, чтобы не стать опцией;
- `nomos_source` сверяет и настоящий путь файла (`realpath`): ссылка внутри корня не выводит за него.

Инструменты MCP только читают (снимок анализа и файлы корня), ничего не пишут и не запускают, кроме `git diff` и `git ls-files`; так ответ модели, на который повлиял текст анализируемого кода, ничего не может изменить.

## CI

- `permissions: contents: read` в обоих workflow;
- все actions закреплены по SHA коммита с версией в комментарии; Dependabot раз в месяц двигает их одним PR (`.github/dependabot.yml`);
- обновления версий npm, NuGet и Go Dependabot не предлагает: новая версия зависимости — решение; уязвимости приходят security updates, которые включаются в настройках репозитория.

`SECURITY.md` (с русской копией) говорит, как сообщить об уязвимости закрыто и что запускает каждая часть.
