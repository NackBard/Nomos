# D-057. Этап 13: Python

Ответы пользователя в начале этапа (2026-11-06): минимальная версия — Python 3.10; интерпретатор — выбранный в расширении Python для папки, без него — программа из `PATH`; модуль — файл, id — путь с точками, пакет — только общий префикс; без подходящего Python — сообщение с причиной и кнопкой, остальные анализаторы работают. Механизм сред в `extension/` обобщается без языковой логики, отступление от «`extension/` не изменился, кроме реестра» записывается здесь. Проектные решения D-049 (`disabled-by-config`, `message.id` с шаблонами spec и английским `message.text`, UML без новых видов рёбер) подтверждены для Python.

- **Анализатор `analyzers/python`** на Python, только стандартная библиотека: `ast` и `tokenize`. Новых зависимостей нет. `symtable` из плана этапа не понадобился: локальные имена функции дают узлы `ast` (параметры, присваивания, `global`/`nonlocal`), а таблицы `symtable` сопоставляются с узлами только по имени и строке, что ненадёжно при декораторах. Точка входа — `main.py`, запуск `python -I main.py manifest | analyze …`: изолированный режим не читает ни переменные окружения, ни `site-packages`, ни папку анализируемого проекта, а сам анализатор кода проекта не импортирует. Запись байт-кода выключена в `main.py`, поэтому `__pycache__` не появляется ни в установленном расширении, ни в репозитории. Тексты правил и практики — `nomos_python/rules.json` и `practices.json` из `npm run spec-json`.
- **Модуль — файл**, id — путь от корня через точки; `__init__.py` — id своего каталога. Абсолютный импорт ищет модуль с тем же id или с id, оканчивающимся на него: так разрешаются раскладка `src/` и импорт соседнего скрипта; из нескольких кандидатов — с самым длинным общим префиксом с импортирующим модулем. Внешняя цель — пакет верхнего уровня, стандартная библиотека — по `sys.stdlib_module_names` (есть с 3.10). Не читаются `.pyi`, `__pycache__`, `node_modules`, `site-packages`, `build`, `dist`, скрытые каталоги и виртуальные среды (каталог с `pyvenv.cfg`). Подробности — раздел «Python» в `spec/metrics.md`.
- **Единицы и типы.** Класс (в том числе вложенный) и функция верхнего уровня, включая `имя = lambda`; объявления в `if`, `try`, `with` верхнего уровня — объявления модуля. `kind`: `protocol` (наследник `Protocol`, абстрактный), `enum`, иначе `class`; абстрактный класс — с `ABC`, `ABCMeta` или `@abstractmethod`. Строение типов (`members`, `satisfies` по именам членов протокола) — раздел «Python» в `spec/structure.md`.
- **Фазы.** Аннотации — всегда `type-only`, и строковые тоже: это запись типа, а не вызов, а с 3.14 аннотации не вычисляются при определении функции. Так вывод не зависит от версии интерпретатора и от `from __future__ import annotations`. Импорт под `if TYPE_CHECKING:` и всё, что через него названо, — `type-only`. Обычный импорт, даже если имя нужно только аннотациям, — `runtime`: Python его выполняет, и цикл модулей при загрузке реален.
- **Типы без проверки типов.** `manifest.capabilities.semantic` и `facts.analyzer.semantic` — `false`. Тип выражения известен из аннотации, создания экземпляра (`x = Order()`), результата функции с аннотацией и поля известного типа; иначе вызов метода и чтение поля ребра не дают. Поэтому у правил, которые держатся на типах, уверенность `low`: `DSN004`, `DSN005`, `OOP005`. Записи `needs-semantic-model` не понадобились: правила по типам молчат, если тип неизвестен, как в JavaScript (D-055).
- **Парадигмы** — абзац «Для Python» в `spec/paradigms.md`. Глобальное состояние — переменная модуля, которую перепривязывают (`global`, второе присваивание, `+=`) или связывают с литералом списка, словаря или множества, кроме имён в верхнем регистре: без объявлений `let`/`const` это единственный признак изменяемости, который виден в коде. Атрибут класса — изменяемое общее состояние, только если ему присваивают через класс: иначе каждое поле модели Django было бы находкой STR002. Неаннотированный параметр, который вызывается в теле, и возврат `lambda` или вложенной функции дают `hofOrder` 2.
- **Правила** — те же 30, что у TypeScript. STR001 — `not-supported` с сообщением «Python has no goto». PAT, CC006–CC008, FUN001–FUN004, OOP006, PRN кроме PRN007 и SEC002 не написаны. Новые объяснения ALG002 в spec с русским переводом: `searchSetDict` (список вместо множества) и `concatListJoin` (сбор частей в список). `OOP001` не сообщает о полях `dataclass`, `NamedTuple` и `TypedDict`. Материализация в цикле (`ALG003`) — `list`, `tuple`, `set`, `dict`, `sorted` и `.copy()`; выделение памяти — литералы и генераторы коллекций, `lambda`, вызов класса проекта или имени в стиле CapWords (классы по PEP 8). Генераторы списков — циклы для глубины и оценки времени, но не точки решения.
- **Токены.** `f`-строка — один строковый токен, как до 3.12 (с 3.12 `tokenize` дробит её): `loc`, Halstead и клоны одинаковы на любой версии от 3.10. Грамматику даёт интерпретатор пользователя: синтаксис новее его (например, `class C[T]` на 3.10) — файл с `parsed: false` и код 4.
- **Механизм сред в `extension/` (отступление от условия этапа).** У `RuntimeRequirement` новые необязательные поля: `resultField` стал необязательным (результат команды — сам путь), `path` — программы для поиска в `PATH`, `check` — аргументы проверки пригодности программы (код 0), `installUrl` — страница установки. В строках `argument` подставляется `${folder}` — папка анализа. Среда с `path` необязательно зависит от своего расширения: расширение не ставится от имени пользователя, его ответ для папки проверяется `check`, а без него проверяются программы `path` по порядку; путь, который команда вернула в кавычках, читается без них. Если ничего не подошло, показывается сообщение с причиной и кнопкой страницы установки, анализатор пропускается, остальные работают. Код поиска — `findRuntime` в `src/core/bundle.ts`, без `vscode`, с тестами; `check-boundary` проходит. Три новые строки интерфейса переведены. `run-e2e.mjs` ставит в тестовый профиль только обязательные среды (без `path`). Прежняя запись .NET не изменилась.
- **Пакет.** `scripts/package.mjs` кладёт `main.py` и `nomos_python/` в `bundle/python/`; файлы одни на все платформы. Запись реестра: `["${runtime}", "-I", "${bundle}/python/main.py"]` и `runtime` с `extension: "ms-python.python"`, `command: "python.interpreterPath"`, `argument: { "workspaceFolder": "${folder}" }`, `path: ["python3", "python", "py"]`, проверкой `sys.version_info >= (3, 10)` и `installUrl` python.org.
- **Запуск в репозитории.** `analyzers/python/run.mjs` находит Python 3.10+ (`NOMOS_PYTHON`, `python3`, `python`, `py`) и запускает анализатор: команда в `nomos.json` и в `npm run python`/`all` одна для Windows и Linux. CI ставит Python 3.10 — самую старую поддерживаемую версию: на нём идут тесты анализатора, conformance и отчёт по репозиторию.
- **Conformance.** Python есть во всех 18 случаях, кроме `patterns` (исключение: правила PAT не написаны), эталоны посчитаны вручную; `parity` дописан везде, где он есть у TypeScript, и совпадает. Отличия формы, которые требует язык: в `oop-cohesion` поля объявлены аннотациями в теле класса, потому что `__init__` попал бы в WMC, а он сравнивается между языками; в `coupling-martin` импорт ради типа — под `TYPE_CHECKING`, а `SqlRepo` наследует протокол `Repo` явно, и это ребро `runtime`, как любое наследование в Python; в `maintainability` порог `minIndex` 85 (функция `add` на строку короче и даёт MI ≈ 81,6) и окно клонов 25 токенов (строка `a: int = 0` — 5 токенов, при окне 20 восемь строк дали бы ещё и клон внутри файла); в `health` у `Store` 292 поля, чтобы `loc` модуля, как у других языков, был 300; в `complexity-estimates` деление пополам — цикл `while`, которого оценка помечает неточным, степени те же; в `cycles-complex` циклический импорт `ping`/`pong` записан как `import ping`, иначе он не загрузился бы; в `type-structure` `Square` не называет протокол `Shape`, но по именам членов ему соответствует, поэтому `Shape` в его `satisfies`, а не в ребре.

Проверено: тесты анализатора (14: шаблоны текстов против spec, `elif`, `TYPE_CHECKING` и цикл без него, раскладка `src/` и относительный импорт, импорт внутри функции, `f`-строка одним токеном, глобальное состояние, практики, коды возврата, пустая папка, детерминизм), `npm run all` — 102 из 102 на пяти языках с `parity`, `npm run validate`, `dotnet test` (golden SARIF изменился только двумя новыми `messageStrings` ALG002), `go test`, тесты TypeScript, `ci` и harness, тесты расширения (41), `check-boundary`, `check-l10n`, синтаксис анализатора по грамматике 3.10. e2e в настоящем VS Code на папке только с `.py` и без `nomos.json` прошёл: встроенный анализатор запустился на Python из `PATH` (`py`, расширения Python в профиле не было), 14 находок, линзы метрик, диаграмма классов.
