# D-067. Переводы живут в репозитории, отдельных пакетов перевода нет

Просьба пользователя (2026-11-13): вынести русский язык в отдельный пакет, чтобы выпускать его отдельно и чтобы автор, скажем, арабского мог сделать свой пакет и прислать его на рассмотрение.

Решение: переводы остаются в этом репозитории, новый язык приходит pull request'ом и выходит со следующим выпуском пакетов, как в большинстве расширений VS Code. Порядок для переводчика — `docs/TRANSLATING.md` (по-английски: его читают люди других языков). `npm run check-l10n` проверяет любой язык, для которого есть файлы `bundle.l10n.<lang>.json` или `package.nls.<lang>.json`: русский обязан быть полным; у другого языка сломанный аргумент шаблона и неиспользуемый ключ — ошибка, а непереведённые строки — предупреждение одной строкой на файл, потому что VS Code показывает вместо них английский.

Почему не отдельный пакет:

- Меню, команды и настройки (`package.nls.*.json`) VS Code читает только из папки самого расширения; другое расширение может дать их лишь механизмом языковых пакетов VS Code (`localizations`), который переводит весь VS Code и столкнулся бы с официальным пакетом языка.
- Тексты правил и находок лежат в spec и в каталоге правил, их читает и `ci`, которого расширение VS Code не касается.
- Строки `t("…")` вынести можно (ядро уже находит языковые пакеты анализаторов, D-062), но тогда перевод разошёлся бы по двум местам.

Ограничение, записанное в `docs/TRANSLATING.md` и в ROADMAP: ядро знает только английский и русский (`Locale` в `extension/src/core/l10n.ts`, три формы слова в шаблонах `{n|…|…|…}`, `l10n.ru` и `messages.<ключ>.ru` в spec). Файлы нового языка VS Code подхватит сразу, а тексты находок и правил останутся английскими, пока ядро не обобщено: любой код языка, формы слов по `Intl.PluralRules`, `l10n.<lang>` в spec. Это делается до того, как будет принят первый перевод; страницы графа и Score для письма справа налево — тогда же.
