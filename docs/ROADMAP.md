## Перед этапом 13. Порядок в репозитории — сделано

Цель (D-056): с каждым языком в работе читается только своё — общие правила, `spec/`, `contracts/` и папка этого анализатора. Код и контракты не меняются.

- `docs/DECISIONS.md` — индекс в одну строку на решение и открытые вопросы; сами решения — `docs/decisions/D-0xx.md`, текст переносится без правок. Ссылки «D-0xx» в коде и документах остаются как есть.
- Корневой `CLAUDE.md` — правила архитектуры, состояние, команды верхнего уровня и ссылки. Подробности — в `analyzers/csharp/CLAUDE.md`, `analyzers/go/CLAUDE.md`, `analyzers/typescript/CLAUDE.md`, `extension/CLAUDE.md`.
- Этапы 1–12 и миграция .NET-кода — в `docs/roadmap-done.md`; в `ROADMAP.md` остаются этапы 13–18 и «Отложено».
- Сгенерированные копии `rules.json` и `practices.json`, golden-файлы и `package-lock.json` — `linguist-generated` в `.gitattributes` и в `.ignore`.

Готово, когда: корневой `CLAUDE.md` не больше 5 КБ; индекс решений не больше 15 КБ; ни одно решение не потеряно (число записей «D-0xx» до и после совпадает, текст каждой — побайтно); все проверки из начала этого файла проходят.

## Этапы 13–16. Новые языки — сделано

Общее для всех языковых этапов — шаги и чек-лист `docs/EXTENDING.md`, плюс:

- анализатор реализует то, что добавили этапы 9–11: практики, `message.id` с русскими шаблонами, члены типов;
- тексты правил и каталог практик берутся из общего генератора JSON (обобщение `npm run go-rules`), язык добавляется в `npm run all` и в CI;
- признаки парадигм языка — строками таблиц `spec/paradigms.md` (формат строк не менять, его читает harness);
- анализатор едет в общем `.vsix`, а на этапе 18 становится своим языковым пакетом (D-056), поэтому всё, что ему нужно, описано в его записи реестра; среда, которой нет в VS Code, — через поле `runtime` реестра или понятное сообщение о том, что поставить;
- решения о модуле, среде и границах поддержки — новым решением в `docs/decisions/` (D-056); новая зависимость — там же с обоснованием.

Готово, когда (для каждого языка): все случаи conformance пройдены или записаны в `exceptions` с причиной, `parity` дописан, где числа должны совпадать; установленный `.vsix` без `nomos.json` показывает анализ проекта на этом языке; `extension/` не изменился, кроме реестра.

## Этап 18. Выпуск расширения в общее пользование

Цель: любой человек ставит Nomos из Marketplace и видит анализ своего проекта на любом из поддерживаемых языков без исходников Nomos и без `nomos.json`. Перенесён в конец по решению пользователя (D-050): к публикации расширение приходит со всеми языками, практиками, русским языком и UML. Основа готова: анализаторы едут в пакете, `nomos.json` необязателен (D-046), граф читается без объяснений (D-047, D-048).

- **Издатель и правовая часть.** Свой `publisher` в Marketplace вместо заглушки `nomos`, лицензия вместо `UNLICENSED`, `repository`, `CHANGELOG.md`; значок 128×128 PNG для страницы Marketplace (`icon` в `package.json`) по рисунку `media/icon.svg`. Скрипт `package.mjs` перестаёт пользоваться `--skip-license` и `--allow-missing-repository`.
- **Ядро и языковые пакеты (D-056, D-062) — сделано.** Расширение Nomos с каталогом правил и по расширению на каждый анализатор (`extensionDependencies` на ядро). Ядро собирает реестр из `package.json` установленных языковых пакетов и предлагает поставить пакет, когда в папке есть файлы языка без анализатора. Языковой пакет не содержит кода вовсе (нет `main`), поэтому `check-boundary` проверяет только ядро.
- **Пакеты под все платформы в CI.** Матрица `win32-x64`, `win32-arm64`, `linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`, `alpine-x64`; каждый пакет проверяется запуском встроенных анализаторов на платформе, для которой собран.
- **e2e без `nomos.json` в CI**: `npm run e2e -- <папка>` с .NET Install Tool в профиле; на Windows он ещё ни разу не прошёл (мешало обновление VS Code, D-046).
- **Проверка глазами в VS Code**: клики по узлам и линиям графа, полосы, скобки циклов, панель связей, дерево «Paradigms and Skipped Rules».
- **Большие проекты**: время анализа и отрисовки графа на проекте в тысячи типов; свёртка колонок и тихий режим подписей.
- **Публикация**: `vsce publish` по каждой цели; Open VSX (VSCodium, Cursor) — по решению владельца.

Готово, когда: ядро и языковые пакеты опубликованы, ставятся на чистые Windows, Linux и macOS и без `nomos.json` показывают анализ проекта на каждом поддерживаемом языке; ядро без единого языкового пакета ставится и сообщает, какой пакет поставить; CI собирает и проверяет пакеты всех целей.

## Агенты и MCP (D-063) — базовая версия

Отдельное расширение `agents/` (Nomos Agents, зависит от ядра): агент проверки парадигм и практик (`@nomos-review`, настройка — изменённый относительно git код или весь), агент скорости функций (`@nomos-perf`, статические оценки facts и предложения оптимизаций), модель — VS Code или Anthropic API по ключу; MCP-сервер с инструментами по последнему анализу и промптами обоих агентов. Ядро изменилось одним событием `onDidAnalyze` в `NomosApi`.

- Сделано: код, сборка `.vsix` (`npm run package` в `agents`), модульные тесты (`npm test` в `agents`: git, выбор функций, контекст, снимок, MCP по stdio), `check-boundary` и `check-l10n` проверяют и `agents/`, MCP-сервер проверен на `.nomos/` этого репозитория.
- Не сделано: e2e в настоящем VS Code (участники чата, команды, регистрация MCP-сервера); ответ настоящей модели ни разу не получен; русские строки глазами; сборка `.vsix` агентов в `npm run package` ядра и публикация вместе с выпуском (этап 18).

Готово, когда: установленные ядро и Nomos Agents в чистом профиле дают ответы `@nomos-review /changes` и `@nomos-perf` через модель VS Code и через ключ Anthropic; агентный режим Copilot видит инструменты сервера Nomos; Claude Code подключает сервер по `node agents/out/mcp/server.js --snapshot .nomos`.

## Отложено

Записано, чтобы не потерять; в этапы не входит, пока пользователь не решит иначе.

- **Диаграмма пакетов UML** — модули и `import` между ними. Данные уже есть в facts; после этапа 11 это вторая галочка на уровне модулей и ещё один формат выгрузки.
- **Диаграмма последовательности** для выбранной функции. Нужен граф вызовов с порядком и ветвлениями — новое необязательное поле facts, которого сейчас нет; рёбра `call` без порядка не годятся.
