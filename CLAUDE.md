# CLAUDE.md

Nomos — статический осмотр кода: статистика и наблюдения-эвристики для разработчика, без порогов приёмки и вердиктов (D-021). Анализаторы по одному на язык, на родных инструментах (`analyzers/<язык>/`, D-020); общие `contracts/`, `spec/`, `conformance/`; расширение VS Code (`extension/`) и `ci/` только показывают результат. Отвечать по-русски, коммитить только по просьбе.

## Где что

- Порядок работ — `docs/ROADMAP.md`, сделанное — `docs/roadmap-done.md`.
- Решения — `docs/decisions/D-0xx.md`, список и открытые вопросы — `docs/DECISIONS.md`. Новое решение — новый файл и строка в списке.
- Агенты и MCP-сервер — `agents/` (D-063): `npm test` там; ядро даёт им `NomosApi.onDidAnalyze`.
- Баллы и панели — `score/` (D-065, формулы `spec/score.md`): единственное место, где есть баллы-оценки; ядро, анализаторы и `ci` их не знают. Двойной щелчок графа ядро отдаёт команде из `nomos.inspect.command` в `package.json` расширения.
- Подробности анализатора или расширения — `CLAUDE.md` в его папке; читать только ту, где работа.
- Архитектура — `docs/ARCHITECTURE.ru.md`, добавить язык — `docs/EXTENDING.ru.md`, перевод — `docs/TRANSLATING.md` (D-067), каталог правил — `docs/ANALYZERS.ru.md` (генерируется).
- Публичные документы (D-068): `README`, `ARCHITECTURE`, `EXTENDING`, `conformance/README` — английский файл и русский `.ru.md` рядом; правка одного — правка обоих.

## Правила

- В `extension/` и `ci/` нет языко-специфичной логики: только контракты и `nomos.json` (`npm run check-boundary`).
- Изменение `contracts/*` — новая `schemaVersion` и решение: необязательное поле — минорная, остальное — мажорная. Анализатор не меняет контракт сам — это предложение пользователю. Текущие версии — `x-contractVersion` в `contracts/*.schema.json`.
- Формулы — `spec/metrics.md`, правила — `spec/rules/*.yaml`, подавления — `spec/suppressions.md`, члены типов и UML — `spec/structure.md`, парадигмы — `spec/paradigms.md`. Без записи в spec правило не реализуется; новое правило входит хотя бы в одну практику.
- Эталоны conformance считаются вручную, не из вывода анализатора.
- Никаких `--fail-on`, оценок и кодов возврата от числа находок; порог в spec — чувствительность детектора; сырые метрики выводятся всегда.
- Находка: `confidence` и непустое объяснение. Вывод детерминирован: без времени, абсолютных путей, случайных id, порядок — Ordinal.
- Правило с парадигмой без её признака — запись в `skippedRules` с причиной.
- Текст находки — шаблон `messages` правила в spec с русским `ru` (D-052, `spec/l10n.md`); сначала spec, потом код. Строки интерфейса — `t("…")` с переводом в `l10n/bundle.l10n.ru.json` (`npm run check-l10n`).
- После правки spec: `npm run spec-json` и `npm run rules-doc` в `conformance/runner`; общее изменение проверяется на всех языках: `npm run all`.
- Новая зависимость — в решении с обоснованием.
- CI — Ubuntu и Node 22.18, локально новее: скрипты проверять и на ней (D-035).
