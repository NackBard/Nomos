# Спецификация баллов Nomos Score

Баллы считает отдельный пакет Nomos Score (D-065) из facts и находок последнего анализа; ни анализаторы, ни ядро, ни `ci` их не считают и не выводят. Как и балл здоровья (`spec/metrics.md`), каждый балл — число от 0 до 100 с выводом: из каких составляющих он сложен и что ушло в недобор. Оценок (A–F), порога «пройдено», кодов возврата и выгрузки «прошёл / не прошёл» нет (D-021): балл показывает, где смотреть, а не принимает работу.

Все входы — поля контракта facts и SARIF; названия языков и их конструкций формулам не нужны. Порядок всего выводимого — по убыванию величины, при равенстве — Ordinal по id. Значения округляются до одного знака только при показе.

## Обозначения

- **Единица** и **граф единиц** — как в `spec/metrics.md`: типы и свободные функции; рёбра `dependencies` любого `kind` и `phase`, кроме внешних, свёрнутые к владеющей единице, без петель и повторов. `N` — число проектных единиц анализа.
- `BR(u)` — blast radius единицы (`spec/metrics.md`): число единиц, которые зависят от `u` прямо или транзитивно. `FO(u)` — обратная величина: число единиц, от которых `u` зависит прямо или транзитивно, без самой `u`.
- `soft(x, h) = 100 / (1 + (x / h)²)` для `x ≥ 0`: 100 при нуле, 50 при `x = h`, плавно к нулю дальше. `h` — чувствительность, а не граница.
- `mean` — среднее по определённым (не `null`) значениям; если определённых нет, результат `null`. `wmean` — то же с весами.
- Вес модуля `w(m) = max(1, loc(m))`.

## Составляющие модуля

Каждая — число от 0 до 100 или `null`, если для модуля не определена.

| Составляющая | Формула | `null`, когда |
|---|---|---|
| `mainSequence` | `100 × (1 − D)` | `D = null` |
| `acyclic` | 0, если модуль в цикле уровня `module`; иначе `100 × (1 − c / u)`, `c` — единицы модуля в циклах уровня `type`, `u` — все его единицы | у модуля нет единиц и он не в цикле |
| `containment` | `100 × (1 − max BR(u) / (N − 1))` по единицам модуля | `N ≤ 1` или у модуля нет единиц |
| `coupling` | `mean(soft(CBO, 10))` по типам модуля | нет типов с CBO |
| `cohesion` | `mean(100 / max(1, LCOM4))` по типам модуля | нет типов с LCOM4 |
| `typeSize` | `mean(soft(WMC, 40))` по типам модуля | нет типов с WMC |
| `inheritance` | `mean(soft(DIT, 4))` по типам модуля | нет типов с DIT |
| `maintainability` | `wmean(maintainabilityIndex)` по функциям модуля, вес `max(1, lines)` | нет функций с индексом |
| `complexity` | `wmean(soft(cyclomatic, 15))` по функциям модуля, вес `max(1, lines)` | нет функций со сложностью |
| `findings(G)` | `100 × exp(−штраф / KLOC / 20)` по находкам модуля категорий группы `G` | ни одна категория группы не запускалась |

`findings(G)` — формула балла категории из `spec/metrics.md` («Балл здоровья») с параметрами по умолчанию: `штраф = Σ severityPenalties[серьёзность] × confidenceFactors[уверенность]`, `KLOC = max(loc / 1000, 0.2)`. Запускавшиеся категории — `health.categories` в facts; если `health` нет — категории, у которых есть находки. Находка относится к модулю своего `module`, без него — к модулю файла.

Группы категорий: **Design** — Design, Paradigm, Principles, Security и всякая категория, не названная в другой группе; **Code** — Maintainability, Algorithms.

## Баллы модуля

| Балл | Составляющие |
|---|---|
| Устойчивость (`stability`) | `mainSequence`, `acyclic`, `containment` |
| Расширяемость (`extensibility`) | `coupling`, `cohesion`, `typeSize`, `inheritance` |
| Соответствие практикам (`conformance`) | `findings(Design)` |
| Сопровождаемость (`maintainability`) | `maintainability`, `complexity`, `findings(Code)` |
| Итог (`overall`) | четыре балла выше |

Балл — `mean` своих составляющих с равными весами; итог — `mean` четырёх баллов. Неопределённая составляющая не входит в знаменатель и называется в выводе: модуль из одних свободных функций не получает ни `mainSequence`, ни расширяемости, и это видно.

## Баллы системы

Каждый балл модуля для системы — `wmean` по модулям с весом `w(m)`. Сверх них у системы есть **масштабируемость** (`scalability`) — `mean` трёх составляющих графа единиц:

- `propagation = 100 × (1 − PC)`, где `PC = Σ BR(u) / (N × (N − 1))` — стоимость распространения изменения (propagation cost, MacCormack и др.): доля системы, которую в среднем задевает правка одной единицы. `N ≤ 1`: `null`.
- `core = 100 × (1 − s / N)`, `s` — размер наибольшего цикла уровня `type` (0 без циклов). `N = 0`: `null`.
- `decomposability = 100 × (1 − 2R)` — разложимость по устойчивости к выбыванию узлов (R, Schneider и др.). Граф единиц берётся неориентированным; единицы выбывают по одной в порядке убывания степени (число соседей; при равенстве — Ordinal по id). `S(q)` — доля `N`, которую занимает наибольшая компонента связности после выбывания `q` единиц; `R = (1/N) × Σ S(q)` по `q = 1…N`, `0 ≤ R < 0.5`. `R` около 0,5 — граф держится вместе, сколько самых связанных единиц ни убери: сцепление сплошное, частью систему не вынести; около 0 — система уже разделена или распадается на независимые части после выбывания немногих узлов, и эти узлы видны в списке узлов распространения. `N = 0`: `null`.

Итог системы — `wmean` итогов модулей; масштабируемость в него не входит и показывается рядом: она описывает граф целиком, а не модули.

## Перколяция

Кривая `S(q / N)` строится для двух порядков выбывания: по степени (как в `decomposability`) и по `BR` (при равенстве — по степени, затем Ordinal). **Критическая доля** — наименьшее `q / N`, при котором `S(q) ≤ S(0) / 2`; она отвечает на вопрос, сколько самых связанных единиц нужно убрать, чтобы система распалась на независимые части. Если граф без рёбер, кривая не строится.

## Ядро и периферия

Классы единиц по видимости (Baldwin, MacCormack): `BR(u)` — входящая видимость, `FO(u)` — исходящая. Высокая — больше медианы по всем единицам и больше нуля. **Ядро** — обе высокие; **общая** — высокая только входящая; **управляющая** — только исходящая; **периферия** — обе низкие. Медиана чётного числа значений — среднее двух средних.

## Зоны Мартина

На диаграмме `A × I` модуль с `D ≥ 0.5` лежит в **зоне боли**, если `A + I < 1` (стабильный и конкретный: много зависящих, мало абстракций, правка дорога), и в **зоне бесполезности**, если `A + I > 1` (абстрактный, но от него никто не зависит). 0,5 — чувствительность диаграммы.

## Недобор и ключевые проблемы

Итог системы раскладывается по местам без остатка: составляющая `c` балла `s` модуля `m` уносит

```
lost(m, s, c) = w(m) / Σ w × (100 − c) / |составляющие s у m| / |баллы у m|
```

пунктов итога системы, где знаменатели считают только определённые значения, а `Σ w` — по модулям с определённым итогом. `Σ lost = 100 − итог системы`. Ключевые проблемы — места с наибольшим `lost`; у каждой — модуль, составляющая, её входы (например, `I`, `A` и `D` для `mainSequence`) и подсказка, что обычно её поднимает.

Отдельно выводятся **узлы распространения** — единицы с наибольшим `BR`, у которых `BR / (N − 1) ≥ 0.25`: правка в них задевает не меньше четверти системы. 0,25 — чувствительность списка.
