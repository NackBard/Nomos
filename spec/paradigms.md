# Парадигмы и признаки стиля

Парадигма — строковый идентификатор. Набор открыт: новый анализатор может объявить свою парадигму в `manifest.paradigms`, добавив её описание сюда. Известные значения: `oop`, `functional`, `structural`.

## Принцип применимости

1. Анализатор объявляет, какие парадигмы поддерживает язык (`manifest.paradigms`).
2. Для каждого модуля он ищет **признаки** (evidence) и записывает их в `modules[].paradigmEvidence`.
3. Правило с непустым `paradigms` применяется к модулю только при наличии признака хотя бы одной из его парадигм (таблица ниже).
4. В остальных модулях правило **не молчит**: в `skippedRules` попадает запись `{ ruleId, module, reason: "paradigm-not-detected", message }` с пояснением вроде «OOP rule not applicable: module has no classes».
5. Правило с пустым `paradigms` применяется всегда.

Конфигурация (`nomos.json` → `paradigms`) может только *отключить* парадигму для языка. Она не создаёт признаков, которых нет в коде: иначе правила ООП сработали бы на модуле без классов.

Два механизма независимы (D-034):

- **Активность** (`modules[].activeParadigms`) — что показывает код. Вычисляется только по признакам с отметкой «да» в таблицах ниже, конфигурация её не меняет. Расширение считает стили модулей по этому полю.
- **Включённость** — какие парадигмы разрешены для языка конфигурацией или умолчанием анализатора. Для C# по умолчанию включены `oop` и `structural` (D-011); список в `nomos.json` заменяет умолчание.

Правило применяется к модулю, если хотя бы одна его парадигма и активна в модуле, и включена. Правило, которое из-за конфигурации не запускалось совсем, получает запись `disabled-by-config` без `module`. Правило, которое запускалось, но в этом модуле все активные парадигмы правила выключены, получает `disabled-by-config` с `module`. Отсутствие признака всегда записывается как `paradigm-not-detected`, в том числе для выключенной парадигмы: запись описывает код, а не настройку.

## Виды признаков

Идентификатор вида — `<префикс>.<имя>`; префикс соответствует парадигме.

### oop

| Вид | Признак | Условие активации парадигмы |
|---|---|---|
| `oop.classes` | типы вида class/struct/record с хотя бы одним методом, полем или свойством | **да** |
| `oop.mutable-state-classes` | классы с изменяемым экземплярным состоянием | нет |
| `oop.inheritance` | типы проекта, наследующие типам проекта | нет |
| `oop.abstractions` | интерфейсы, абстрактные классы, протоколы | нет |

Парадигма `oop` активна в модуле, если есть признак `oop.classes`.

### functional

| Вид | Признак | Условие активации парадигмы |
|---|---|---|
| `fp.pure-functions` | функции, чистота которых доказана консервативным правилом ниже | **да** |
| `fp.higher-order` | функции, принимающие или возвращающие функции | **да** |
| `fp.lambdas` | лямбды, переданные как аргументы | нет |
| `fp.immutable-types` | типы класса, структуры или записи с экземплярными полями или свойствами, среди которых нет изменяемых (все поля `readonly`, у свойств нет сеттера, кроме `init`) | нет |

### Чистая функция

Определение консервативно: лучше не признать чистой функцию, чем признать чистой функцию с эффектом. Функция (метод или свободная функция с телом, не конструктор и не аксессор) чиста, если одновременно:

1. она пишет (присваивание, `++`, `--`, составное присваивание) только в свои локальные переменные и параметры, переданные по значению, и не имеет параметров `ref`/`out`/`in`;
2. она читает поля и свойства только если они константы или только для чтения, либо принадлежат аргументу или локальной переменной; статические члены стандартной библиотеки читаются только из `System.Math`;
3. она вызывает только члены `System.Math`, члены `System.String` и чистые функции проекта (наибольшая неподвижная точка: цикл вызовов между чистыми функциями допустим);
4. она создаёт только строки и типы проекта без явных конструкторов;
5. в ней нет `await`, вызовов делегатов и синтаксиса, который анализатор не разобрал.

Из-за этих ограничений признак занижен: функции с LINQ, коллекциями или вызовом внешних библиотек чистыми не считаются, даже если фактически без эффектов. Это граница метода, а не оценка кода.

Парадигма `functional` активна, если есть хотя бы один признак с отметкой «да». Лямбды активации не дают: передача лямбды в библиотечный метод (LINQ) встречается в обычном объектном коде и говорит об использовании чужого API, а не о стиле модуля. Анализатор записывает `fp.lambdas` как статистику (D-033).

### structural

| Вид | Признак | Условие активации парадигмы |
|---|---|---|
| `str.free-functions` | функции вне типов | **да** |
| `str.control-flow` | функции с ветвлениями или циклами | **да** |
| `str.global-state` | переменные уровня модуля, статические изменяемые поля и свойства | нет |

Для языков, где любая логика лежит в методах (C#), `str.control-flow` присутствует почти всегда, и структурная парадигма активна почти везде. Это ожидаемо: правила `structural` обращены к размеру и глобальному состоянию, они применимы любому императивному коду.

Следствие таблицы: модуль из одного статического класса-хранилища без ветвлений не активирует `structural`, и `STR002` к нему не применяется, хотя признак `str.global-state` записан. Правило получает запись `paradigm-not-detected`, а признак виден в facts.

Для Go: `oop.mutable-state-classes` — любая структура с полями, `oop.inheritance` — встраивание проектной структуры, `str.global-state` — переменные пакета. `fp.immutable-types` не выводится: неизменяемых полей в языке нет. В определении чистой функции стандартные `System.Math` и `System.String` заменяются пакетами `math` и `strings`, допустимы встроенные `len`, `cap`, `min`, `max`; функциональные литералы, `go`, `defer` и работа с каналами запрещены. Умолчания конфигурации те же, что у C#: включены `oop` и `structural`.

## Запись признака в facts

```json
{ "paradigm": "oop", "kind": "oop.mutable-state-classes", "count": 3,
  "description": "classes with mutable instance state", "examples": ["Shop.Orders.Cart", "Shop.Orders.Order"] }
```

`examples` — не более пяти идентификаторов в порядке Ordinal. Описание на английском.

## Парадигма как информация

Признаки сами по себе — статистика для разработчика: расширение показывает «какой стиль используется в модуле» и не оценивает его. Смешение парадигм не является проблемой, пока правило не говорит об обратном.
