# Язык интерфейса и тексты находок

Nomos показывает интерфейс, правила и находки по-русски, когда VS Code русский, и по-английски в остальных случаях (D-052). Анализ от языка не зависит: анализатор не знает локали, его вывод одинаков при любом языке интерфейса. Переводит клиент — расширение или `ci --locale ru`.

## Что где лежит

| Текст | Английский | Русский | Кто подставляет |
|---|---|---|---|
| Название, описание, обоснование правила | `title`, `description`, `rationale` в `spec/rules/*.yaml` | `l10n.ru` того же правила | расширение, `ci`, `docs/ANALYZERS.md` |
| Название и описание практики | `spec/practices.yaml` | `l10n.ru` практики | расширение, `docs/ANALYZERS.md` |
| Сообщение и объяснение находки | `messages.<ключ>.text` правила | `messages.<ключ>.ru` | расширение, `ci` |
| Интерфейс расширения | строки кода, `package.nls.json` | `extension/l10n/bundle.l10n.ru.json`, `package.nls.ru.json` | `vscode.l10n` |
| Отчёты `ci` | строки кода | `ci/l10n/bundle.l10n.ru.json` | `ci --locale ru` |

`npm run spec-json` (`conformance/runner`) переносит правила и практики в JSON: `extension/rules.json`, `extension/practices.json`, `ci/rules.json` и файлы анализатора Go. `npm run validate` проверяет, что они не устарели.

## Шаблоны

Шаблон — текст с местами для аргументов:

- `{n}` — аргумент номер `n`, с нуля;
- `{n|одна|две|пять}` — только в переводе: форма слова для числа в аргументе `n` по правилам русского языка (1, 21 — первая; 2–4, 22 — вторая; 0, 5–20, 11–14 — третья; дробное — вторая). Число само не выводится, его пишут отдельно: `{1} {1|строку|строки|строк}`;
- `{{` и `}}` — фигурные скобки.

Английский шаблон (`text`) — это ровно тот текст, который анализатор выдаёт в `message.text` или `properties.explanation`, с аргументами на местах. Перевод использует те же аргументы, что и английский шаблон, не больше и не меньше. `npm run validate` проверяет и это, и синтаксис; `npm run check-l10n` (`extension`) — что у каждого шаблона, правила, практики и строки интерфейса есть русский текст.

Ключ шаблона — имя в camelCase, уникальное внутри правила. Сообщения и объяснения лежат в одном словаре `messages`. Два ключа одного правила не могут иметь одинаковый `text`: по тексту анализатор находит ключ.

Ключ не меняет своих аргументов (D-062). Ядро переводит находки по своему каталогу, а языковой пакет может быть собран с другим (D-056): ядро подставит аргументы анализатора в свой шаблон этого ключа. Поэтому шаблон, у которого меняется набор аргументов, получает новый ключ, а старый удаляется; формулировку при тех же аргументах можно менять под прежним ключом. `npm run spec-json` сравнивает новый каталог с `extension/rules.json` и ничего не пишет, если у ключа изменились аргументы. Ключа, которого нет в каталоге ядра, оно не переводит и показывает `message.text`.

## Что делает анализатор

1. Каждый текст находки строится из шаблона своего правила. В C# `Report` принимает интерполированную строку (`FormattableString`), в Go — `tx(формат, аргументы…)` с литералом формата. Тест каждого анализатора читает эти строки из исходников и требует, чтобы они были шаблонами spec (`MessageTemplateTests`, `TestTemplatesAreInSpec`): так проверяются и ветви, до которых не доходит ни одна фикстура.
2. Аргументы форматируются без учёта культуры: `0.52`, а не `0,52`.
3. **В аргументах нет английских слов.** Имена из кода, числа, пути и код — можно. Слово, которое пришлось бы переводить, становится частью шаблона: два варианта текста — два ключа (`DSN001.pain` и `DSN001.uselessness`). Список эффектов функции в FUN001 записан как код (`total = …`, `Console.WriteLine()`, `DateTime.Now`), а не фразами.
4. В SARIF анализатор кладёт ключ и аргументы рядом с английским текстом (`contracts/sarif-profile.md`): `message.id`, `message.arguments`, `properties.explanationMessage.{id, arguments}`, а в описание правила — `messageStrings` с английскими шаблонами. Harness проверяет, что текст получается из шаблона и аргументов.

## Что не переводится

- Тексты facts, которые пишет анализатор: `health.explanation`, `diagnostics[].message`, `skippedRules[].message`. Причину пропуска расширение переводит по коду `reason` (с невыбранными практиками, которые оно знает само), а признаки парадигм — по виду (`oop.classes`…). Английский текст анализатора остаётся в отчётах `ci` и в подсказках.
- Ошибки нарушения контрактов (схемы facts, SARIF, manifest): они адресованы автору анализатора.
- Имена метрик (`cyclomatic`, `lines`…) и id правил: это идентификаторы spec, как имена в коде.
- Базовая линия `ci`: она хранит английский текст, чтобы сравнение не зависело от языка отчёта.
