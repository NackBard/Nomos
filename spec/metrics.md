# Спецификация метрик

Единственное описание формул. Каждый анализатор считает метрики сам, своими родными средствами, но по этому документу. Совпадение результатов между языками проверяет `conformance/`. Изменение формулы — это изменение контракта: запись в `docs/DECISIONS.md` и перегенерация эталонов.

Все метрики — измерения. Порогов приёмки здесь нет: значения попадают в facts как есть, а правила (`spec/rules`) лишь решают, когда о значении стоит сообщить.

`null` в facts означает «метрика не определена для этой сущности». Это не ноль.

## Общие определения

- **Единица (unit)** — тип либо свободная функция, не вложенная в тип. Графы зависимостей строятся над единицами.
- **Проектная единица** — единица внутри `--root`. Зависимость на внешнюю (`external: true`) цель в графах Ca, Ce, циклов и blast radius не участвует; для CBO внешние нестандартные цели участвуют.
- **Граф зависимостей** — рёбра `dependencies` с `kind` любого вида и `phase` любой: для Ca, Ce, CBO и blast radius `runtime` и `type-only` равноправны, зависимость по типу тоже связывает код. Циклы строятся только по рёбрам `runtime` (см. Тарьян, D-055). Рёбра с `from` или `to` на уровне функции сворачиваются к владеющей единице; рёбра на уровне модуля (`import`) в графах единиц не участвуют, но участвуют в графе модулей (см. Тарьян). Петли (ребро в себя) отбрасываются.
- **Модуль единицы** — модуль, которому принадлежит единица.

## Языки без классов

Формулы не меняются, меняется то, что считается их входом. Для Go (D-038):

- единица — именованный тип уровня пакета или свободная функция, модуль — пакет, его id — путь импорта;
- `struct` — аналог `class`, интерфейс — абстрактный тип; у `foreignMembers` исключение для структур не действует, потому что других носителей состояния в языке нет;
- встраивание типа — ребро `inheritance` и шаг DIT, встроенный интерфейс в DIT не входит; реализация интерфейса в Go неявна, поэтому ребра не даёт, а записывается в `types[].satisfies` (spec/structure.md);
- все методы экземплярные, закрытых методов нет: у TCC и LCOM4 участвуют все методы с телом;
- `case` с несколькими значениями даёт по точке решения на значение, `catch` и тернарного оператора нет;
- цикл только с условием — `while`; `append` — растущая операция, `make` с нелитеральным размером — массив, `&T{}`, `new`, `make`, литералы срезов и карт и функциональные литералы — выделение памяти;
- запоминание — чтение карты в двух значениях `v, ok := m[k]`;
- импорт пакета — ребро `import`, циклы модулей не могут появиться в компилируемом коде.

## TypeScript и JavaScript

Один анализатор на оба языка (D-055); формулы те же, вход такой:

- модуль — файл, его id — путь от корня без расширения (`src/shop/cart`); два файла с одним путём без расширения сохраняют расширение;
- единица — класс, интерфейс, `enum`, псевдоним типа (`type`) и функция верхнего уровня: `function`, а также `const f = () => …` и `const f = function …`; объявления в теле IIFE верхнего уровня (`(function () { … })()`) считаются объявлениями модуля; пространства имён (`namespace`) и код верхнего уровня вне функций единиц не дают;
- абстрактный тип — интерфейс, `abstract class` и псевдоним объектного типа (`type P = { … }`);
- метод — метод класса, конструктор и свойство класса со стрелочной функцией или функциональным выражением; аксессоры `get`/`set` — аксессоры, пара с одним именем — один член в `memberCount`; параметр-свойство конструктора (`constructor(private x: X)`) — поле;
- закрытый метод для TCC — `private` или `#имя`; статические методы в LCOM4, TCC и `foreignMembers` не участвуют;
- `phase: type-only` — ссылка, стираемая при компиляции: позиция типа (аннотация, аргумент типа, `implements`, `extends` интерфейса, `typeof` в типе), любая ссылка на интерфейс или псевдоним типа и `import`, чьи имена используются только как типы, если `verbatimModuleSyntax` и `preserveValueImports` выключены; `import type` и `export type` — всегда. `extends` класса — `runtime`. В JavaScript все рёбра `runtime`;
- `call` — вызов, `new`, тег шаблонной строки, JSX-элемент, обращение к статическому члену или значению `enum`; чтение поля — `type-ref`;
- `import` — `import`, `export … from`, `import x = require()`, вызов `require("…")` и `import("…")` с литералом; имя из `const { f } = require("…")` ведёт к функции или классу другого модуля;
- `??`, `?.` и составные логические присваивания точек решения не дают, как и в C# и Go;
- `for…of` и `for…in` — обход; растущие операции — `push`, `unshift`, `Set.add`, `Map.set`; массив нелитерального размера — `new Array(n)`, `Array(n)`, `Array.from({ length: n })`; выделение памяти — `new`, литералы массива и объекта, лямбды и выражения класса;
- известные линейные операции — методы последовательностей (`includes`, `indexOf`, `find`, `filter`, `map`, `forEach`, `reduce`, `some`, `every`, `flat`, `flatMap`, `join`, `slice`, `concat`, `fill`, `reverse`, `keys`, `values`, `entries`, `Array.from` и аналоги) на получателе из библиотеки или неизвестного типа; методы строк линейными не считаются, их `n` — длина одной строки, а не размер входа; сортировка — `sort`, `toSorted`;
- запоминание — `таблица.has(ключ)` или `ключ in таблица`; деление пополам — `/ 2`, `>> 1`, `>>> 1` (в том числе внутри `Math.floor`);
- типы в JavaScript — то, что выводит компилятор, и JSDoc (`@param {Order} order`); ссылки внутри JSDoc рёбер не дают.

## Python

Анализатор на `ast` и `tokenize` стандартной библиотеки (D-057). Проверки типов нет: имя разрешается по областям видимости и импортам, тип выражения — только из аннотаций и явного создания. Формулы те же, вход такой:

- модуль — файл `.py`, его id — путь от корня без расширения, через точки (`shop.orders.cart`); `__init__.py` даёт id своего каталога (`shop.orders`), `__init__.py` в самом корне — `__init__`; если два файла получают один id, второй по Ordinal пути сохраняет `.__init__`. Пакет — только общий префикс id, своей сущности у него нет. Файлы `.pyi`, каталоги `__pycache__`, `node_modules`, `site-packages`, `build`, `dist`, скрытые и каталоги виртуальных сред (с `pyvenv.cfg`) не читаются;
- абсолютный импорт `a.b` ведёт к модулю с id `a.b` или с id, оканчивающимся на `.a.b` (каталог `src/` и папка скрипта — корни поиска): из нескольких выбирается тот, у кого с импортирующим модулем длиннее общий префикс, затем более короткий, затем первый по Ordinal. Относительный импорт считается от пакета модуля. `from p import x` ведёт к модулю `p.x`, если он есть, иначе к `p`. Стандартная библиотека — `sys.stdlib_module_names`, её цель и цель внешнего пакета — имя пакета верхнего уровня (`os`, `requests`);
- единица — класс (в том числе вложенный в класс, id `модуль.Внешний.Внутренний`) и функция верхнего уровня: `def`, `async def` и имя, связанное с `lambda`. Объявления в блоках `if`, `try` и `with` верхнего уровня считаются объявлениями модуля, вложенные в функции — нет;
- `kind` типа: `protocol` — наследник `Protocol`; `enum` — наследник `Enum` и его вариантов; иначе `class`. Абстрактный тип — протокол и класс, у которого есть база `ABC` или метакласс `ABCMeta` либо хотя бы один метод с `@abstractmethod`;
- метод — функция в теле класса; `__init__` — конструктор; функция с `@property` и её `@x.setter` и `@x.deleter` — аксессоры, их пара — одно свойство в `memberCount`; `@staticmethod` и `@classmethod` — статические. Неявные `self` и `cls` в `parameterCount` не входят; `*args`, `**kwargs`, параметры только позиционные и только именованные считаются;
- поле — аннотация или присваивание в теле класса и присваивание `self.x` в методах. Присваивание в теле класса без аннотации и `ClassVar[…]` — статическое поле. Закрытое имя — с `_` в начале, кроме `__имя__`; у функций верхнего уровня такое имя — `internal`. Для TCC закрытые методы — закрытые по имени;
- `phase: type-only` — аннотация (параметра, результата, переменной, поля), строковая аннотация и всё, что импортировано или объявлено под `if TYPE_CHECKING:`; аннотации записаны в коде как типы, а не как вызовы, и с Python 3.14 не вычисляются при определении функции. Остальные рёбра `runtime`; импорт, использованный только в аннотациях, тоже `runtime`: Python его выполняет;
- `call` — вызов, создание экземпляра (вызов класса), декоратор, обращение к атрибуту класса и значению `enum` через имя класса; чтение поля через экземпляр — `type-ref`; `import` — `import`, `from … import` в любом месте файла и `importlib.import_module` с литералом;
- тип выражения: `self` и `cls` — свой класс; параметр и переменная — по аннотации (`Optional[T]`, `T | None` и строка `"T"` — сам `T`); переменная, которой присвоено создание класса, вызов функции с аннотацией результата или поле известного типа, — этот тип; элемент обхода коллекции известного элемента — элемент. Остальные вызовы методов и обращения к полям рёбер не дают: тип получателя неизвестен;
- `elif` — точка решения на том же уровне вложенности, что и его `if`; `else:` с одним `if` внутри — вложенный `if`. Метка `case`, кроме `case _:` без условия, — точка решения; `if` генератора — точка решения, его `for` — нет. `with` и `async with` — уровень вложенности; `try` — уровень, каждый `except` — точка решения;
- генераторы списков, множеств, словарей и генераторные выражения — циклы для глубины циклов и оценки времени (каждый `for` — множитель); цикл `for` по `range` с литеральными аргументами и по литералу коллекции или строки — множитель 1;
- растущие операции — `append`, `extend`, `insert`, `add`, `update`, `setdefault`; массив нелитерального размера — `[x] * n`; выделение памяти — литералы списка, множества и словаря, генераторы списков, множеств и словарей, `lambda` и вызов класса проекта или имени с заглавной буквы (классы по PEP 8). Вызовы `list`, `tuple`, `set`, `dict`, `sorted` и `.copy()` — материализация (`ALG003`), а не выделение;
- известные линейные операции — `sum`, `min`, `max`, `any`, `all`, `list`, `tuple`, `set`, `frozenset`, `dict`, `str.join` и методы `index`, `count`, `remove`, `extend`, `copy` на получателе не из проекта, а также `in` по списку или кортежу известного типа; сортировка — `sorted` и `.sort()`;
- запоминание — декоратор `functools.cache`, `functools.lru_cache`, проверка `ключ in таблица` или вызов `таблица.get(ключ)`; деление пополам — `// 2`, `/ 2`, `>> 1`.
- `ALG002` — `in` по списку или кортежу известного типа, `index`, `count` и `insert(0, …)` у списка и `+=` к строке внутри цикла (генератор — тоже цикл); тип известен из аннотации или литерала, иначе находки нет;
- `OOP001` не сообщает о полях `dataclass`, `NamedTuple` и `TypedDict`: открытые поля — их назначение. `f`-строка — один строковый токен (как до Python 3.12), поэтому `loc`, Halstead и клоны не зависят от версии интерпретатора; синтаксис новее интерпретатора пользователя — файл с `parsed: false`.

## Java

Анализатор на javac Tree API (`com.sun.source`) с атрибуцией типов, одна компиляция на все исходники без classpath (D-058, как D-003 для C#): типы JDK разрешаются, типы библиотек остаются неразрешёнными и называются как в `import` (`org.lib.Client`). Формулы те же, вход такой:

- модуль — пакет, его id — имя пакета (`shop.orders`), модуль может состоять из многих файлов; файл без `package` — модуль `(global)`, как глобальное пространство имён C#. Не читаются `module-info.java`, каталоги `node_modules`, `target`, `build`, `out`, `bin` и скрытые;
- единица — тип: класс, интерфейс, `enum`, запись (`record`), аннотация (`@interface`), в том числе вложенный (id `пакет.Внешний.Внутренний`). Локальные и анонимные классы и лямбды единиц не дают, их тела входят в охватывающую функцию;
- `kind`: `class`, `interface`, `enum`, `record`, `annotation`; абстрактный тип — интерфейс, аннотация и `abstract class`. DIT, CBO, LCOM4, WMC, ATFD и TCC определены для `class` и `record`;
- метод — метод и конструктор, написанные в коде; конструкторы, которые добавляет javac (по умолчанию и канонический у записи), и неявный `super()` в них функций и рёбер не дают. id функции — `Тип.имя`, у перегрузок — с типами параметров (`Тип.f(int)`, `Тип.f(java.lang.String)`), конструктор — `Тип.Тип`;
- поле — переменная в теле типа; `static final` с константой времени компиляции — `constant`, значение `enum` — `literal`, компонент записи — свойство: его чтение через аксессор (`r.x()`) — чтение свойства (`type-ref`, член для ATFD и `ownMembers`). Без модификатора — `internal` (видно в пакете), члены интерфейса — `public`;
- все рёбра `runtime`: стирания типов, как в TypeScript, нет — класс загружается при выполнении. `extends` и `implements` — `inheritance`; `call` — вызов метода, `new`, явный `super(…)` и `this(…)`, ссылка на метод (`T::m`, `T::new`), обращение к статическому члену и значению `enum`; чтение поля экземпляра, тип, аннотация и `T.class` — `type-ref`. Вызов на значении неразрешённого типа — `call` к этому типу. `import` (в том числе `static` и `.*`) — ребро модулей к пакету цели;
- точки решения — `if`, каждая метка `case` (у `case A, B` — две), кроме `default`, циклы, `catch`, `?:`, `&&`, `||`. Уровни вложенности — `if`, `switch` (оператор и выражение), циклы, `try` (в том числе с ресурсами), `synchronized`;
- функциональный тип — функциональный интерфейс по javac (`Function`, `Runnable`, свой с одним абстрактным методом); его глубина — 1 плюс глубина аргументов типа, у других обобщённых типов и массивов — глубина аргументов. Проверка типа — `instanceof` (с образцом тоже) и образец типа в `case`;
- обход литеральной коллекции — массив-инициализатор и `List.of`, `Set.of`, `Stream.of`, `Arrays.asList` с литералами; известные линейные операции — методы потоков (`filter`, `map`, `reduce`, `collect`, `anyMatch`, `count`, `toList` и аналоги), поиск и массовые операции коллекций (`contains`, `indexOf`, `remove(Object)`, `removeIf`, `containsAll`, `forEach`, `toArray`), помощники `Collections` и `Arrays` (`max`, `min`, `frequency`, `fill`, `copyOf`) и `String.join`; у `Set` и `Map` поиск константный. Сортировка — `sort` (`List`, `Collections`, `Arrays`) и `sorted` потока;
- растущие операции — `add`, `addAll`, `put`, `putAll`, `push`, `offer` и варианты, `append`, `insert`, `computeIfAbsent`; массив нелитерального размера — `new T[n]`; выделение памяти — `new` (объект и массив) и лямбда. Материализация в цикле (`ALG003`) — `toList`, `toArray`, `collect` потока или коллекции и `copyOf` у `List`, `Set`, `Map`, `Arrays`;
- запоминание — `containsKey`, `computeIfAbsent` или `get` у `Map`; деление пополам — `/ 2`, `>> 1`, `>>> 1`;
- `ALG002` — `contains`, `indexOf`, `lastIndexOf` и `add(0, …)` у `List` и `+=` к `String` внутри цикла; `SEC003` — склейка `+`, `String.format` и `formatted` со значением, которое не константа; `SEC001` — инициализатор и присваивание строкового литерала, а также `put("ключ", "литерал")`.

## Виды рёбер зависимостей

Ребро `dependencies` имеет ровно один `kind`; если один тип связан с другим по нескольким причинам, рёбер несколько (по одному на вид). Вид определяется по самому сильному признаку в таком порядке:

| `kind` | Когда |
|---|---|
| `inheritance` | цель — базовый класс или реализуемый интерфейс в объявлении типа-источника |
| `call` | в теле источника создаётся экземпляр цели, вызывается её член или обращение идёт к её статическому члену |
| `type-ref` | любое другое упоминание: тип поля, свойства или события, тип параметра или результата, тип локальной переменной, приведение, проверка типа, `typeof`, атрибут |
| `import` | директива подключения на уровне модуля (`using`, `import`); источник и цель — модули |

Рёбра разных видов между одной парой единиц не заменяют друг друга: граф зависимостей строится по паре, а вид нужен читателю и расширению.

## Размер

| Метрика | Определение |
|---|---|
| `lines` функции или типа | `последняя строка − первая строка + 1`, где первая строка содержит первый токен сигнатуры (без атрибутов и документирующих комментариев), последняя — закрывающий токен тела. Пустые строки и комментарии внутри считаются |
| `loc` файла и модуля | число строк, содержащих хотя бы один токен, не являющийся комментарием. Для модуля — сумма по его файлам |
| `parameterCount` | число объявленных параметров без неявных (`this`, `self`, `cls`, получатель расширения). Необязательные и именованные считаются. Параметр-вариадик — один |
| `memberCount` типа | поля, свойства, события, методы, конструкторы, вложенные типы (без вложенного содержимого). Аксессоры свойств отдельно не считаются |
| `methodCount` типа | методы и конструкторы, без аксессоров |

## Цикломатическая сложность

`cyclomatic = 1 + число точек решения` в теле функции. Точки решения:

- `if` и каждая ветвь `else if` (простой `else` не считается);
- каждая метка `case`/`when`/ветвь `match`, кроме ветви по умолчанию;
- циклы: `for`, `foreach`/`for in`, `while`, `do`;
- каждый `catch`/`except`;
- условное выражение `?:` / `x if c else y`;
- каждый короткозамкнутый логический оператор (`&&`, `||`, `and`, `or`);
- `if` внутри генератора списка и аналогичных конструкций.

Лямбды и локальные функции входят в сложность охватывающей функции и отдельной записи в `functions` не получают, если язык не делает их самостоятельными именованными единицами.

## Вложенность

`maxNesting` — наибольшее число одновременно охватывающих конструкций у любого оператора функции. Считаются: `if`, `switch`/`match`, циклы, `try`, `lock`/`using`/`with`. Тело функции — уровень 0. Ветка `else if` лежит на том же уровне, что и её `if`. Тело лямбды продолжает вложенность охватывающей функции.

## Признаки стиля функции

Выводятся для каждой функции в `functions[].metrics`, правила `FUN005` и `OOP003` сообщают о них по своим порогам.

| Метрика | Определение |
|---|---|
| `hofOrder` | `1 + d`, где `d` — наибольшая глубина вложенности функциональных типов в типах параметров и результата. Только данные: 1. Принимает или возвращает функцию от данных: 2. Принимает функцию от функции: 3 |
| `lambdaNesting` | наибольшее число лямбд, вложенных друг в друга в теле функции. Без лямбд: 0 |
| `typeTests` | число различных проектных типов, которые функция проверяет во время выполнения (`is`, сопоставление с типом, `isinstance`). Повторная проверка того же типа не считается |

## Оценки сложности функции

Это оценки формы кода, а не измерения: размеры входов неизвестны. Выводятся для каждой функции в `functions[].metrics` независимо от порогов; `ALG001`, `ALG003`, `ALG004` сообщают о них. У функции без тела все значения этого раздела — `null`.

| Метрика | Определение |
|---|---|
| `timeDegree` | степень `k` в оценке времени `O(nᵏ · logˡ n)`; `null`, если оценка экспоненциальная (у неё нет степени) |
| `timeLogFactor` | степень `l` логарифма в той же оценке; `null`, если оценка экспоненциальная |
| `timeExponential` | 1, если оценка экспоненциальная, иначе 0 |
| `spaceDegree` | степень дополнительной памяти, см. ниже |
| `allocationDepth` | наибольшая глубина циклов, на которой функция создаёт объект ссылочного типа (массив тоже) или лямбду. Без них: 0 |

**Глубина циклов** узла — число циклов, чьё тело его содержит. Заголовок цикла, который выполняется один раз (инициализаторы, итерируемое выражение), к телу не относится.

**Оценка времени** вычисляется снизу вверх. Последовательность и ветвления дают наибольшую из оценок частей, цикл умножает оценку тела на множитель цикла:

- цикл `for` c литеральной границей, литеральным началом и условием вида `i < 10`, а также обход литеральной коллекции: 1;
- `for` с шагом, делящим или умножающим счётчик (`/=`, `*=`, `>>=`, `<<=`, `i = i / 2`): `log n`;
- `while`/`do`, в теле которых счётчик делится так же: `log n`;
- любой другой цикл: `n`;
- обход элемента внешнего обхода (`foreach (var c in node.Children)` внутри цикла по `node`): 1, это обход иерархии, он линеен по общему размеру (D-010).

Вызов внешней функции из языкового списка известных линейных операций (поиск, фильтр, агрегат, материализация; список — дело анализатора) даёт `n`, умноженное на оценку переданной лямбды; сортировка даёт `n log n`; обращения к таблицам с поиском за константу и прочие внешние вызовы — 1. Вызов проектной функции даёт её оценку. Функции вычисляются в порядке Ordinal по id; вызов функции, которая ещё вычисляется (взаимная рекурсия), даёт 1.

**Рекурсия.** Пусть `c` — наибольшее число прямых вызовов себя на одном пути выполнения (взаимоисключающие ветви не складываются, охранное условие с выходом исключает остаток блока), `w` — оценка тела без учёта рекурсии.

| Форма | Оценка |
|---|---|
| `c ≤ 1`, аргумент делится пополам | `log n · w` |
| `c ≤ 1`, аргумент уменьшается на константу | `n · w` |
| `c > 1`, аргумент делится пополам | `max(w, n) · log n` |
| `c > 1`, аргумент изменяется на константу, без запоминания | экспоненциальная |
| `c > 1`, аргумент изменяется на константу, с запоминанием | `n · w` |
| аргумент не делится и не меняется арифметически (обход структуры) | `max(w, n)` |

Запоминание — проверка таблицы в теле функции (`TryGetValue`, `ContainsKey`).

**`spaceDegree`** — наибольшее из значений: глубина циклов вызова внешней растущей операции (`Add`, `Push`, `Enqueue`, `Insert` и аналоги языка); `d + s` для массива на глубине `d` с `s` измерениями нелитерального размера; 1 при прямой рекурсии (глубина стека). Без них: 0.

Порог `reportFromDegree` сравнивается со степенью, экспоненциальная оценка `ALG001` сообщается всегда, `measured` тогда — `timeExponential`. `minDepthForObjects` сравнивается с глубиной каждого места; `measured` содержит `allocationDepth` функции, то есть наибольшую из них. Материализация в цикле (`ALG003`) порога не имеет и `measured` не содержит.

## Связность и сцепление (ООП)

Определены для типов вида `class`, `struct`, `record` и аналогов.

- **DIT** — длина самой длинной цепочки рёбер `inheritance` от типа вверх до корня, считая только базовые классы (не интерфейсы). Универсальный корень языка (`object`) не считается. Внешний базовый класс — один шаг, его собственные предки неизвестны и не учитываются. Тип без базы: 0.
- **CBO** — число различных других типов, на которые типу указывают рёбра зависимостей (любой `kind`) из него самого и его методов. Проектные цели и внешние нестандартные цели считаются, `stdlib: true` и сам тип — нет.
- **LCOM4** — число компонент связности графа, чьи вершины — экземплярные методы типа (без конструкторов и статических). Ребро: два метода обращаются к одному экземплярному полю или один вызывает другой. Свойство с автоматическим полем считается полем. Меньше одного метода: `null`.
- **WMC** — сумма `cyclomatic` методов и конструкторов типа (аксессоры, как и в `methodCount`, не входят).
- **ATFD** — число различных атрибутов (полей и свойств) других **проектных** типов, к которым тип обращается напрямую или через аксессор. Атрибуты внешних типов не считаются: их состав между языками несопоставим. Статические члены не считаются.
- **TCC** — `NP_connected / NP`, где `NP = n(n−1)/2` для `n` видимых методов типа, `NP_connected` — число пар, обращающихся к общему полю. Видимые методы — не `private` экземплярные методы с телом (без конструкторов и статических). При `n < 2`: `null`.

Для экземплярных методов с телом (в `functions[].metrics`, у остальных функций `null`):

- **foreignMembers** — наибольшее по чужим типам число различных экземплярных полей и свойств одного другого проектного типа вида `class` и аналогов, к которым метод обращается через доступ к члену. Записи и структуры не считаются: их данные предназначены для чтения. Унаследованный член принадлежит типу, где объявлен. Нет обращений: 0.
- **ownMembers** — число различных полей и свойств своего типа, к которым обращается метод.

`DSN005` сообщает при `foreignMembers ≥ minForeignMembers` и `foreignMembers > ownMembers`.

## Метрики Мартина по модулю

Над единицами, как определено выше.

```
Ca = |{ t вне m : существует ребро t → u, u ∈ m }|     (афферентная связанность)
Ce = |{ u вне m, проектная : существует ребро t → u, t ∈ m }|   (эфферентная)
I  = Ce / (Ca + Ce)               null при Ca + Ce = 0
A  = число абстрактных типов m / число типов m     null при отсутствии типов
D  = |A + I − 1|                  null, если A или I равны null
```

Абстрактный тип — `isAbstract: true` (интерфейс, абстрактный класс, протокол, trait). Модуль только из свободных функций имеет `A = null`, а значит и `D = null`: честнее, чем притворяться, что он конкретный.

## Циклы (Тарьян)

Алгоритм Тарьяна ищет сильно связные компоненты. Выводятся компоненты с двумя и более участниками (петли не считаются). Оба уровня строятся только по рёбрам с `phase: runtime`: цикл, замкнутый стираемыми ссылками, при выполнении не существует (D-055). В C# и Go все рёбра `runtime`, для них это ничего не меняет.

- Уровень `type`: граф единиц.
- Уровень `module`: ребро `M → N`, если есть ребро между единицами этих модулей или ребро `import` на уровне модуля, `M ≠ N`.

Участники внутри компоненты отсортированы по Ordinal; компоненты — по первому участнику. Результат — `cycles` в facts.

## Blast radius

`blastRadius(t)` — число различных проектных единиц, достижимых из `t` по обращённым рёбрам графа зависимостей (то есть всех, кто прямо или транзитивно зависит от `t`), без самой `t`. Для функции — blast radius владеющей единицы; для функции без единицы (вложенной в модуль) — число единиц, зависящих от неё напрямую или транзитивно по тем же правилам.

## Слои

Правило `DSN003` работает по `layers` из `nomos.json`. Шаблон в `patterns` сравнивается с id модуля целиком, без учёта регистра; `*` означает любую подстроку, в том числе пустую. Модуль принадлежит первому слою, чей шаблон подошёл. Нарушение — проектная зависимость единицы из слоя `S` на единицу другого слоя `T`, когда `T` нет в `S.mayDependOn`; транзитивно разрешения не наследуются. Зависимости внутри одного модуля или слоя и зависимости модулей вне всех слоёв не проверяются. Если `layers` пуст или не задан, правилу не на чем работать: запись `skippedRules` с причиной `missing-input`.

## Шаблоны (ООП)

Определены для типов вида `class`, `struct`, `record`.

- **settableProperties** — свойства с публичным сеттером (`PAT102`).
- **forwardingMethods** — наибольшее по членам типа число публичных методов, тело которых состоит из одного вызова через это поле или свойство. `PAT103` сообщает, когда так устроены все публичные методы типа и их не меньше `minMethods`.

## Дублирование

Клон — последовательность не короче `minTokens` токенов, равная другой после замены идентификаторов и литералов заполнителями; строки директив подключения не считаются. `cloneTokens` — длина такой последовательности. Она принадлежит паре фрагментов, а не сущности, поэтому в facts не выводится, только в `measured` у `MNT003`.

## Покрытие

`files[].coverage` — `100 × покрытые строки / строки отчёта` по файлу, где покрыта строка с числом выполнений больше нуля. Отчёт (Cobertura, если расширение `.xml`, иначе LCOV) задаётся в `nomos.json`: `rules.MNT004.threshold.report`, путь относительно `--root`. Запись отчёта относится к файлу, если её путь равен пути файла или оканчивается на `/` и этот путь, без учёта регистра. Если отчёт не указан или файла нет, `MNT004` получает запись `missing-input`, а поля нет. Файл, которого нет в отчёте, поля не получает: это не ноль. Файл из отчёта без строк: 100.

## Индекс сопровождаемости

```
V  = N × log2(n)       Halstead volume; N — все операторы и операнды, n — различные
MI = max(0, (171 − 5.2·ln V − 0.23·G − 16.2·ln L) × 100 / 171)
```

`G = cyclomatic`, `L = lines` функции. Считаются токены всех строк функции, сигнатура входит. Операнды — идентификаторы и литералы; операторы — ключевые слова и знаки операций. Разделители `( ) { } [ ] ; ,` и комментарии не считаются. `V = 0` или `L = 0`: `null`. Границы токенов различаются по языкам, поэтому для `halsteadVolume` и `maintainabilityIndex` в conformance задан широкий допуск (относительный 15 %); эти поля показывают порядок величины, а не точное сравнение между языками.

## Балл здоровья

Балл — число и его вывод. Оценки (A–F) и порога «пройдено» нет.

```
штраф(категория, модуль) = Σ severityPenalties[серьёзность] × confidenceFactors[уверенность]   по результатам категории в модуле
KLOC                     = max(loc модуля / 1000, minKloc)
балл категории           = 100 × exp(−штраф / KLOC / decayPerKloc)
балл модуля              = Σ (балл категории × вес категории) / Σ веса    по категориям, которые реально запускались
балл проекта             = Σ (балл модуля × loc модуля) / max(1, Σ loc)
```

Значения по умолчанию: `severityPenalties = { info: 0, minor: 1, major: 3, critical: 8 }`, `confidenceFactors = { low: 0.25, medium: 0.6, high: 1 }`, `decayPerKloc = 20`, `minKloc = 0.2`, вес любой категории 1. Параметры меняются в `nomos.json` → `scoring`.

Категория, правила которой были пропущены для модуля целиком, не входит в знаменатель модуля. Результат без модуля относится к модулю его файла. Каждый балл сопровождается `explanation` и разбивкой по категориям: что ушло в штраф.

Баллы разных языков сопоставимы только при одинаковом наборе запущенных категорий: набор указан в `categories`.

## Допуски в conformance

Целые числа и идентификаторы сравниваются точно. Для `instability`, `abstractness`, `distance`, `tcc` по умолчанию абсолютный допуск 0,001. Для `halsteadVolume` и `maintainabilityIndex` — относительный 15 %. Переопределения задаются в `case.json`.
