# Спецификация структуры типов

Что анализатор пишет в необязательные поля facts 1.3.0 о строении типов и функций и как из них получается диаграмма классов UML. Это описание фактов, а не метрика: порогов и оценок нет. Поля необязательны; анализатор, который их не заполняет, остаётся совместимым, а диаграмма для его языка показывает только имена типов и связи из `dependencies`.

Порядок везде — порядок объявления в исходнике. У типа из нескольких частей (`partial` в C#, методы Go в разных файлах) — по пути файла (Ordinal), затем по строке.

## Члены типа: `types[].members`

Состояние и интерфейс типа, кроме функций (они в `functions` с `type`). Вложенные типы членами не считаются, у них своя запись в `types`.

| Поле | Смысл |
|---|---|
| `name` | Имя как в коде. У встроенного поля Go — имя типа без пакета и `*`. |
| `kind` | `field` — поле; `property` — свойство (C#); `event` — событие (C#); `constant` — константа (`const` в C#); `literal` — значение перечисления. |
| `visibility` | Как у `functions[].visibility`. Go: экспортируемое имя — `public`, иначе `internal` (видно в пакете). Член интерфейса C# без модификатора — `public`. |
| `typeName` | Текст типа из исходника, переводы строк и повторы пробелов сжаты в один пробел: `List<Order>`, `[]*Order`, `map[string]int`. Нет у `literal`. |
| `type` | id типа проекта, о котором член: сам тип, а для коллекции — тип элемента. Только если тип разрешён и объявлен в проекте; иначе поля нет. |
| `isStatic` | Член принадлежит типу, а не экземпляру. Константы и значения перечисления — `false`: статичность у них подразумевается и на диаграмме не показывается. |
| `isCollection` | Тип — коллекция элементов, см. ниже. |
| `isEmbedded` | Go: встроенное поле (`struct { Base }`). |

**Коллекция.** C#: массив; тип из `System.Collections.Generic`, `System.Collections.Immutable`, `System.Collections.ObjectModel`, `System.Collections.Concurrent`, а также `IEnumerable<T>`, у которого есть аргумент. Go: срез, массив, карта, канал. Элемент — последний аргумент типа: значение у словаря и карты. Указатель, `Nullable<T>`, `T?` коллекцией не делают: `type` — сам `T`.

Наследуемые члены не повторяются: у типа только его собственные. Члены, сгенерированные компилятором (поле автосвойства, `EqualityContract` записи), не пишутся. Позиционные параметры записи C# — свойства.

## Параметры типа: `types[].typeParameters`

Имена параметров обобщённого типа по порядку: `["TKey", "TValue"]`. Ограничения не пишутся. У необобщённого типа поля нет.

## Функции: `parameters`, `returnTypeName`, `isStatic`, `isAbstract`

- `parameters` — `{ name, typeName }` по порядку. `typeName` записан как в коде; модификаторы `ref`, `out`, `in`, `params` и `...` входят в него (`ref int`, `...string`). Нет типа (лямбда без типов) — поля `typeName` нет. Получатель метода Go — не параметр.
- `returnTypeName` — тип результата как в коде. Нет у конструктора, у `void` и у функции Go без результатов. Несколько результатов Go — список в скобках, как в коде: `(int, error)`.
- `isStatic` — статический метод. В Go `false` у всех: методов без получателя нет, а свободная функция — не член типа.
- `isAbstract` — метод без реализации: `abstract`, член интерфейса без тела. Методы интерфейса Go — функции с `type` интерфейса и `isAbstract: true`.

## Неявная реализация: `types[].satisfies`

Языки со структурной типизацией (Go) реализуют интерфейс без упоминания его в коде. `satisfies` перечисляет id интерфейсов проекта, которые тип реализует так: в Go — `types.Implements` для `T` или `*T`. Сам интерфейс, интерфейсы без методов и внешние интерфейсы не перечисляются; у интерфейса поля нет.

Это не зависимость: в коде нет упоминания, поэтому ребра в `dependencies` нет, и Ca, Ce, CBO, DIT, циклы и blast radius от `satisfies` не зависят. Язык с явной реализацией (C#) поля не пишет, реализация у него — ребро `inheritance`.

## TypeScript и JavaScript

Анализатор `analyzers/typescript` (D-055) пишет поля так:

- `members`: поле класса, параметр-свойство конструктора, свойство интерфейса и объектного псевдонима типа — `field`; пара аксессоров `get`/`set` с одним именем — одно `property` (тип — из аннотации геттера, иначе сеттера); значение `enum` — `literal`. Свойство класса со стрелочной функцией — метод, а не член. `#имя` пишется как в коде и закрыто (`private`).
- `visibility`: `private` (модификатор или `#`), `protected`, иначе `public`; у функций верхнего уровня — `public` при `export`, иначе `internal` (видна в модуле).
- `typeName` — аннотация как в коде; без аннотации поля нет (в JavaScript его нет почти всегда). `type` и `isCollection` — по типу аннотации: `T[]`, `Array`, `ReadonlyArray`, `Set`, `ReadonlySet`, `Map`, `ReadonlyMap`, `WeakMap`, `WeakSet`, `Iterable` с аргументом — коллекция, элемент — последний аргумент; `T | null | undefined` — сам `T`.
- `parameters`: параметр `this` не пишется; у остаточного параметра `typeName` начинается с `...` (`...string[]`); деструктуризация — её текст как имя. `returnTypeName` — аннотация результата, без аннотации и у `void` поля нет.
- `isStatic` — `static`; `isAbstract` — `abstract` и методы интерфейсов и объектных псевдонимов.
- `satisfies` — у необобщённого класса: интерфейсы проекта с хотя бы одним членом, которым экземпляр класса присваиваем по проверке компилятора, кроме названных в `implements` и `extends` самого класса и его баз (они — рёбра `inheritance`). Типизация TypeScript структурная, поэтому, как и в Go, реализация без упоминания в коде существует; ребра она не даёт.

## Python

Анализатор `analyzers/python` (D-057) пишет поля так:

- `members`: аннотация или присваивание в теле класса и присваивание `self.x` в методах — `field`, по порядку первого появления (сначала тело класса, затем методы по порядку); атрибут класса без аннотации и `ClassVar[…]` — `isStatic`; пара `@property` с `@x.setter` — одно `property` с типом из аннотации результата геттера; значение `enum` (присваивание в теле наследника `Enum`) — `literal`. Атрибут, которому присвоена `lambda`, — тоже поле: Python не отличает его от данных.
- `visibility`: имя с `_` в начале, кроме `__имя__`, — `private`, иначе `public`; у функций верхнего уровня такое имя — `internal`.
- `typeName` — аннотация как в коде, строковая аннотация — без кавычек; без аннотации поля нет. `type` и `isCollection` — по аннотации: `list`, `set`, `frozenset`, `dict`, `tuple[T, ...]`, `deque`, `defaultdict` и их варианты из `typing`, а также `Sequence`, `Iterable`, `Mapping` и другие коллекции `collections.abc` с аргументом — коллекция, элемент — последний аргумент; `Optional[T]`, `T | None` и `Union[T, None]` — сам `T`.
- `typeParameters`: аргументы базы `Generic[…]` и `Protocol[…]`, а также параметры `class C[T]` (Python 3.12).
- `parameters`: `self` и `cls` методов не пишутся; `*args` пишется именем `*args`, `**kwargs` — `**kwargs`. `returnTypeName` — аннотация результата; без неё и у `None` поля нет.
- `isStatic` — `@staticmethod` и `@classmethod`; `isAbstract` — `@abstractmethod` и методы протокола, тело которых — только `...`, `pass` или строка документации.
- `satisfies` — у необобщённого класса: протоколы проекта с хотя бы одним членом, все методы и поля которых есть у класса или его баз проекта по имени, кроме протоколов, названных в базах. Сигнатуры не сравниваются: проверки типов нет, это граница метода.

## Java

Анализатор `analyzers/java` (D-058) пишет поля так:

- `members`: поле — `field`; `static final` с константой времени компиляции — `constant`; значение `enum` — `literal`; компонент записи — `property` с видимостью `public` (его читают через аксессор). Поля интерфейса — `public` и статические, а с константой — `constant`.
- `visibility`: `public`, `protected`, `private`, без модификатора — `internal` (видно в пакете); члены и методы интерфейса без модификатора — `public`.
- `typeName` — тип как в коде; `type` и `isCollection` — по типу, который вывел javac: массив, наследник `Collection` или `Map`, `Iterable` и поток с аргументом — коллекция, элемент — последний аргумент (значение у `Map`); `Optional<T>` — сам `T`.
- `typeParameters` — параметры обобщённого типа без границ. id обобщённого типа их не содержит: `ts.Drawing`, а не `ts.Drawing<T>`.
- `parameters`: параметр-получатель (`Тип this`) не пишется; у параметра переменной длины `typeName` кончается на `...` (`String...`). `returnTypeName` — тип результата как в коде; у `void` и конструктора поля нет.
- `isStatic` — `static`; `isAbstract` — метод без тела: `abstract` и метод интерфейса без `default`.
- `satisfies` не пишется: реализация в Java явная и даёт ребро `inheritance`.

## Kotlin

Анализатор `analyzers/kotlin` (D-059) пишет поля так:

- `members`: параметры первичного конструктора с `val` или `var`, затем члены тела в порядке объявления, члены `companion object` — на его месте. Свойство — `property`, с `@JvmField` — `field`, `const val` — `constant`, значение `enum` — `literal`; члены `companion object` и объявления `object` — статические (`isStatic`), кроме `const val`.
- `visibility`: `public` (умолчание Kotlin), `internal`, `protected`, `private`; члены интерфейса без `private` — `public`.
- `typeName` — тип как в коде, у свойства без объявленного типа поля нет; `type` и `isCollection` — по объявленному типу, а без него — по инициализатору (создание класса, `mutableListOf<T>()` и аналоги). `List`, `Set`, `Map`, `Collection`, `Iterable`, `Sequence`, `Array` и их изменяемые варианты с аргументом — коллекция, элемент — последний аргумент (значение у `Map`); `T?` — сам `T`.
- `typeParameters` — параметры обобщённого типа без границ; id обобщённого типа их не содержит.
- `parameters`: получатель функции-расширения не пишется; у `vararg` `typeName` начинается с `vararg ` (`vararg String`). `returnTypeName` — тип результата как в коде; у `Unit`, функции без объявленного результата и конструктора поля нет, у аксессора `get` — тип свойства.
- `isAbstract` — метод без тела в интерфейсе и `abstract`; `isStatic` — члены `companion object` и `object`.
- `satisfies` не пишется: реализация в Kotlin явная и даёт ребро `inheritance`.

## Связи диаграммы классов

Диаграмма строится по типам выбранного модуля (или двух модулей) и связям между ними. Связь рисуется, только если оба конца — типы проекта на диаграмме. Обобщение, реализация, встраивание и ассоциации независимы: класс может и наследовать тип, и хранить ссылку на него (Composite). Ассоциация рисуется на каждый член отдельно. Зависимость — только если между парой в ту же сторону нет ни одной другой связи.

| Связь UML | Откуда | Обозначение |
|---|---|---|
| Встраивание | член с `isEmbedded` и `type` | сплошная линия, закрашенный ромб у владельца, стереотип «embed» |
| Обобщение | ребро `inheritance`, цель не interface/protocol/trait, или источник и цель оба интерфейсы | сплошная линия, пустой треугольник у цели |
| Реализация | ребро `inheritance` от не-интерфейса к типу вида interface, protocol или trait; запись в `satisfies` | пунктир, пустой треугольник у цели |
| Ассоциация | член с `type` без `isEmbedded` | сплошная линия, стрелка к типу члена, подпись — имя члена, кратность `*` при `isCollection` |
| Зависимость | ребро `type-ref` или `call` между типами, если между ними в ту же сторону нет другой связи | пунктир, открытая стрелка |

Ребро `inheritance` к типу, встроенному членом, — встраивание, а не обобщение: в Go встраивание даёт и член, и ребро.

## Отделения класса

- Заголовок: стереотип по `kind`, кроме `class` — «interface», «struct», «enum», «record», «delegate»; у абстрактного не-интерфейса имя курсивом; параметры типа — `Name<T, U>`.
- Атрибуты: `members` по порядку, `знак имя: typeName`; значения перечисления — только имя. Событие — со стереотипом «event»; свойство пишется как поле, иначе в C# пометка стояла бы почти у каждой строки.
- Операции: `functions` с этим `type`, кроме `accessor` и `lambda`, в порядке строк: `знак имя(п: Тип, …): Результат`; параметр без имени — только тип; конструктор — без результата.
- Длинное отделение на странице графа сворачивается: видны первые строки и «+N» вместо остальных; в выгрузке — все строки.
- Знаки видимости: `public` `+`, `private` `-`, `protected` `#`, `internal` `~`, `unspecified` — без знака. Статический член подчёркнут, абстрактная операция — курсивом.

В выгрузке PlantUML и Mermaid порядок типов — по id (Ordinal), связей — по (от, к, вид, имя члена), так что выгрузка детерминирована.
